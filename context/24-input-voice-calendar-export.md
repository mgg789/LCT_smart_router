# Голосовой ввод, календари, экспорт: вспомогательные механики (ресерч 2026-09)

> Фича-контекст: ввод заявки голосом («диктуем по телефону»), синхронизация планов с календарями, печать/экспорт дня. Все — дешёвые добавки поверх ядра с ощутимым wow на демо.

## 1. Голосовой ввод заявки (русский)

Варианты реализации:

| Вариант | Как работает | Плюсы | Минусы | Вердикт |
|---|---|---|---|---|
| **faster-whisper локально** | WebM/Audio → POST на наш GPU-бэкенд (CTranslate2, large-v3/distil; до 4× быстрее Whisper при той же точности — [GitHub](https://github.com/SYSTRAN/faster-whisper)) | Полный офлайн (сцена!), отличная точность на русском, GPU PRO 6000 у нас есть | Нужен эндпоинт (~30 строк FastAPI) + запись с микрофона (MediaRecorder) | **Основной вариант** |
| Web Speech API (Chrome) | `SpeechRecognition` c `lang=ru-RU` | Ноль инфраструктуры | У русского **облачный** режим Google (нужен интернет, нестабильно на сцене); локальный режим Chrome 139+ пока без ru-RU ([Chrome 139](https://developer.chrome.com/blog/new-in-chrome-139), [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API), [explainer](https://github.com/WebAudio/web-speech-api/blob/main/explainers/on-device-speech-recognition.md)) | Резерв/фолбэк |
| Vosk (офлайн, лёгкий) | Kaldi-модель ru в браузере/на сервере | Крошечная, офлайн | Точность ниже Whisper | Не берём |

Рекомендованный поток: **микрофон (MediaRecorder) → faster-whisper на нашем сервере → текст → уже существующий LLM-парсер заявки (`08` §4) → карточка-подтверждение → заявка**. Голос не добавляет нового AI-риска — он просто альтернативный ввод в тот же пайплайн с подтверждением. Для демо: диктовка заявки голосом в 11:30-сценарии — сильный момент.
Effort: S–M (эндпоинт + кнопка записи + прогресс). Fallback: ручной ввод — всегда на виду.

## 2. Календари инженера (.ics)

- Формат iCalendar (.ics) тривиален: сгенерировать VEVENT с DTSTART/DTEND, SUMMARY (тип работ+адрес), LOCATION (адрес), DESCRIPTION (окно, комплект, ссылка на визит). Библиотеки: JS `ics`/`ical-generator`, Python `icalendar`.
- **Фичи:** (1) кнопка «Добавить визит в календарь» в карточке инженера (индивидуальные .ics); (2) подписка на весь день по URL (`webcal://` feed) — Google Calendar/Apple Calendar сами обновят план при перепланировании (важно: при изменении плана просто перегенерируем feed, UID событий стабильные).
- Google Calendar API/CalDAV полные интеграции не нужны (дорогие ключи, обзор — за рамки хакатона); .ics-фид покрывает 90% ценности бесплатно и офлайн.
- Effort: S. Берём (это «инженер получил план в свой календарь» — реальные операции).

## 3. Экспорт и печать

- **PDF «План дня»** для руководителя: один шаблон (headless-браузер puppeteer/print CSS) — карта (снимок), таблица визитов, метрики, объяснения. Кнопка «Скачать план дня» + «Скачать объяснение плана» (`11` §4). Effort: S–M. Берём: печать — признак «взрослого» продукта, жюри это любит.
- **QR-код** на публичную страницу «инженер в пути» (`23` §4) — на бланке наряда; библиотека `qrcode`. Effort: XS.
- **Экспорт CSV/JSON** датасета и планов — для «интеграции в ИТ-ландшафт Билайна» слайда. Effort: XS.
