# Изменения в концепции после QA-сессии 16.09.2026

> **Статус: «Согласовано»** — решения пользователя от 16.09.2026 по итогам официальной QA-сессии (основания: [47](./47-qa-2026-09-16.md), [48](./48-official-facts-2026-09-16.md), разбор [49](./49-qa-2026-09-16-impact.md)). Это накопительный список правок концепции: **пока затронутые канон-файлы (32/33/34/36/37/38/39) не отредактированы, при любом расхождении приоритет за этим файлом.** Список будет дополняться по мере дальнейших решений.

## 1. Дефолтная политика — `compact`, не `fast`

- **Было:** default `fast` = coverage → travel_time → distance → engineers_used (33 §5, 34 §6.2, `core/policy.py`).
- **Стало:** default **`compact`** = coverage → engineers_used → distance → travel_time. Соответствует официальным критериям QA: 1) больше выполненных заявок, 2) меньше исполнителей; пробег/время в пути — на наше усмотрение (47 §9).
- Затрагивает: 33 §5, 34 §6.2, 39 §6 (default в селекторе политик Dashboard), `core/policy.py`, golden-фикстуры — **план и hash изменятся намеренно**, зафиксировать в теле коммита (AGENTS §4.8).
- Каталог 5 политик сохраняется целиком; `fast` остаётся доступной, просто не дефолт.

## 2. GPS и отслеживание локации инженера — убираем полностью

- **Было:** добровольный GPS-сбор: таблица `gps_observations` (37 §5), GPS-эндпоинт инженера (`engineer.controller`), упоминания GPS в списке источников фактов/прогноза (36 §5), в перечнях сброса (37 §8–9, 39 §10).
- **Стало:** трекинг локации **исключён из продукта полностью** — ни таблицы, ни эндпоинтов, ни UI. Инженеры на карте Dashboard — **только плановые позиции** (39 §5 — остаётся; live-слоя не было и не будет).
- Обоснование: пользователь прототипа — только диспетчер (47 §13); предсказание «где инженер» для однодневной офлайн-задачи не нужно; минус сущность в модели данных и ноль приватностных рисков.
- Затрагивает: 37 §5 (удалить сектор), 36 §5 (убрать GPS из источников фактов), 38 (Engineer App — без GPS), 39 §10 (перечень сброса «всё в ноль»), Prisma-схема и миграции, `engineer.controller` (удалить GPS-эндпоинт), smoke-чеклист.

## 3. Обед — по умолчанию выключен, включается в дашборде

- **Было:** lunch-модель v14 активна в планах по умолчанию (32 §8, 33 §6, 34 §8); в сценариях включена.
- **Стало:** `lunches_enabled=false` **по умолчанию** в официальных сценариях/датасете; включение — переключатель в Dashboard. При включении модель прежняя и не упрощается: окно, длительность, `required`, `lunch_taken` (32 §8).
- Обоснование: организаторы обеды вообще не учитывают (47 §7); критерий №1 «выполненные» не должен страдать от обеда; демо-фича второго эшелона: «план без обедов → включаем → план с обедом». Main и FIFO-baseline всегда считаются при **одинаковой** настройке обеда — иначе сравнение метрик нечестное (49 §6.2).
- Затрагивает: `core/scenarios/*/config.json` (enabled=false), 32 §8 / 33 §6 (default), 39 (переключатель в контролах дня), sys-операция включения (публикует новый снимок — триггеры 36 §1), smoke-сценарий.
