# Домен: выездные инженерные службы и диспетчеризация (Field Service)

> Назначение: словарь домена, роли, процессы. Без понимания «кто и как работает сегодня» нельзя сделать продукт, который диспетчер полюбит. Термины зафиксированы здесь — используем их единообразно в коде, UI и презентации.

---

## 1. Роли и их боли

### Диспетчер (главный пользователь продукта)
**Зона ответственности:** план дня, распределение заявок, реакция на срочное, коммуникация с клиентами и инженерами.

Боли:
- Утром собирает план вручную из Excel/1С/телефонных звонков — 30–60 минут рутинной подгонки.
- Днём каждая срочная заявка — «головоломка»: кому отдать, кого подвинуть, кого предупредить.
- Не видит последствий своих правок: передвинул заявку — сломал день другому инженеру, узнает по звонку из поля.
- Несёт ответственность за SLA, но инструментов прогноза срыва нет — узнаёт об опоздании постфактум.
- Постоянные прерывания: телефон, мессенджер, начальник. Инструмент должен показывать важное сразу, а не требовать внимания.

Что ценно для него: **автоплан, которому можно доверять + мгновенная оценка последствий любых изменений + «что делать при событии» подсказкой, а не констатацией.**

### Руководитель сервиса
Боли: неравномерная загрузка (один в полях 9 часов, другой 4), перевыполнимые/невыполняемые SLA, отсутствие аналитики. Ему — дашборд метрик и сравнение «ручной план vs оптимизированный».

### Инженер
Боли: непонятный маршрут, дефицит времени на переезд, не хватает запчастей/оборудования. Для него продукт — план дня: список визитов с адресами, окнами, комплектом, контактами. Версия «мобильный вид» — nice-to-have.

### Клиент (абонент Билайна)
Хочет: приехали в обещанное окно, не «с 9 до 18». Окно — это обещание, его нарушение = перенос = повторный визит = деньги.

## 2. Ключевые сущности и их атрибуты (словарь домена)

| Сущность | Атрибуты | Нюансы |
|---|---|---|
| **Заявка (work order / request)** | адрес (+координаты), временное окно, тип работ, ожидаемая длительность, приоритет/SLA-класс, требуемые навыки, требуемое оборудование, контакт клиента, статус (новая/запланирована/в пути/выполнена/перенос) | Длительность — оценочная (см. ML-файл); окно может быть узким (1–2 ч) или широким (половина дня) |
| **Инженер (technician)** | ФИО, база (офис/дом — стартовая точка), график смены, навыки (квалификация), транспорт, текущий комплект оборудования, статус (свободен/в пути/на объекте) | Навыки — это «владение типами работ»; может быть уровень (junior/middle) |
| **Тип работ (work type)** | код, название, требуемые навыки, базовая длительность, требуемое оборудование, допустимый транспорт | Матрица «работа → оборудование» дана в ТЗ. Примеры телеком: подключение интернета, замена роутера, ремонт линии, настройка видеонаблюдения, аудит узла |
| **Оборудование (equipment)** | тип, инстансы (комплекты с количеством), совместимость с работами | Ограничение может быть и по количеству (у инженера 3 ONU) и по совместимости |
| **Транспорт (vehicle)** | тип (легковая/фургон), атрибуты (лестница на крыше, крепления под стойку), принадлежность инженеру | «Проверка транспорта» = совместимость работа→транспорт |
| **Временное окно (time window)** | start, end, строгость (жёсткое/предпочтительное) | VRPTW-термин; нарушение жёсткого = заявка не запланирована сегодня, мягкого = штраф |
| **SLA** | класс (VIP/стандарт), обещанное время/окно, допустимая задержка | Штраф за нарушение — главный soft-критерий |
| **План (plan)** | версия, дата, набор назначений (инженер → последовательность визитов с временами), метрики, причины | Версионирование обязательно — см. `07-dynamic-replanning.md` |

## 3. Жизненный цикл заявки

```
поступила → проверена (геокод, совместимость) → запланирована
   → назначена инженеру → уведомлён → выехал → на объекте → работа
   → выполнена / не выполнена (перенос на завтра, отказ клиента)
```

Для хакатона важны первые 4 стадии + «перенос». Статусы «в пути/на объекте» — для симуляции дня (time scrubber в демо).

## 4. Жизненный цикл дня диспетчера (сценарий использования)

1. **Накануне вечером / утром 8:00** — формируется базовый план дня (всё, что накопилось + подтверждённые визиты). Наш сервис: кнопка «Построить план» → секунда → просмотр и корректировка.
2. **Утро 9:00** — инженеры получают маршруты. Неявки/болезни — событие «инженер недоступен» → перепланирование.
3. **День 10:00–18:00** — поток событий: новая срочная заявка (SLA 2 часа), клиент просит перенести, инженер задержался, закончились комплекты. На каждое: сервис пересчитывает план и **показывает дельту**.
4. **Вечер** — разбор: что не успели, метрики дня.

Дизайн-вывод: главный экран = **план дня** (карта + таймлайн), события прилетают поверх, дельта — первоклассный объект интерфейса, а не лог в консоли.

## 5. Специфика телеком-выездов (контекст Билайна)

- Работы: подключение интернета/ТВ/телефонии, замена/настройка оборудования (роутер, ONU, STB), ремонт линии, монтаж видеонаблюдения, обслуживание B2B-объектов (офисы, магазины).
- Клиент физически присутствует → окно жёсткое, приезд «мимо окна» = перенос.
- Оборудование материальное: не привёз ONU — работа не выполнена → матрица совместимости критична.
- Часть работ требует конкретной квалификации (сварка волокна ≠ настройка роутера).
- Город: выезды равномерно по городу с кластеризацией по районам — это важно для генерации реалистичных данных (см. `14-data-model.md`).

## 6. Что такое «хороший план» в глазах каждого

| Роль | Хороший план — это... |
|---|---|
| Диспетчер | Стабильный, доверие: не меняется без причины, изменения объяснены и показаны |
| Клиент | Приехали в окно |
| Инженер | Логичный маршрут по району, не «через весь город на 20 минут» |
| Руководитель | Равномерная загрузка, минимальные переносы, предсказуемость |

Эти четыре взгляда = наши четыре критерия оптимизации. Они же — текст для презентации.

## 7. Терминологическая карта EN↔RU (для кода и документации)

- Work Order / Заявка; Technician / Инженер; Dispatch / Диспетчеризация
- Time Window / Временное окно; SLA (Service Level Agreement) / Соглашение об уровне сервиса
- Skill / Навык (квалификация); Equipment / Оборудование; Vehicle / Транспорт
- Route / Маршрут; Schedule / Расписание; Replanning / Перепланирование
- Travel time / Время в пути; Service time / Время работы (на объекте)
- Depot / База (точка старта/финиша); Utilization / Загрузка
