# Лог принятых решений (ADR-стиль)

> Назначение: все ключевые архитектурные/продуктовые решения в одном месте с обоснованием и условием пересмотра. Любой агент, сомневающийся «почему так», находит ответ здесь; менять решение — только через новую строку в этом логе (не молча).

Формат: **D-№ · Решение · Альтернативы · Обоснование · Статус · Пересмотреть, если…**

| ID | Решение | Альтернативы | Обоснование | Статус | Пересмотреть, если |
|---|---|---|---|---|---|
| D-1 | Солвер: OR-Tools Routing (GLS) как ядро | Timefold Python, VROOM, PyVRP, самописный ALNS | Зрелость, наша модель ограничений собирается из коробки; на масштабе 20–100 заявок пересчёт — мс (`05`) | Принято | Прототип в день 0 покажет, что Timefold даёт лучше score-breakdown за то же время (`05` §3) |
| D-2 | Мульти-цель: лексикография SLA > баланс > пробег через веса-штрафы | взвешенная сумма, паретто | Понятно жюри и диспетчеру; включение следующей цели после насыщения предыдущей (`04` §4) | Принято | Если организаторы зададут официальные веса/штрафы SLA |
| D-3 | Причины решений — rule-based из данных солвера (кандидаты, дельты, контрфакты) | LLM-генерация причин, только текстовые заглушки | Пункт ТЗ №5 требует честности; детерминизм и проверяемость (`11`) | Принято | Никогда (ядро продукта) |
| D-4 | Перепланирование: тёплый старт от предыдущего плана + штраф стабильности; полная пересборка при утреннем build | инкрементальные структуры, solver-daemon | Стабильность плана важнее «идеальности» для доверия; масштаб позволяет пересборку, но она трясёт план (`07` §2–3) | Принято | Если дельты окажутся слишком вялыми при срочных заявках — усилить вес SLA относительно стабильности |
| D-5 | Гео: self-hosted OSRM (MLD) для матрицы/маршрутов + кэш | 2GIS/Яндекс API как основной, Valhalla, GraphHopper | Офлайн-демо, бесплатно, быстро (`06` §2–3) | Принято | Никогда для ядра; 2GIS — как дополнительный провайдер ETA |
| D-6 | Подложка карты: Yandex Tiles (free, ключ) → резерв CARTO Voyager → офлайн self-host тайлы | MapTiler, OSM raster публичный | Лучшая Москва бесплатно; полированный светлайт под UI (`20` §1–2) | Принято | Если ToS Яндексов окажется неудобным (атрибуция/запреты) — CARTO основной |
| D-7 | Пробки: исторические коэффициенты по часам + (опц.) 2GIS Directions «live»-ETA + data.mos.ru дорожные работы | попытка скрести Яндекс-пробки, честный «нет трафика» | Легальность; два независимых источника дают правдоподобие и слайд зрелости (`20` §3, `22` §2) | Принято | Если получим доступ к потоковым данным от организаторов/Билайна |
| D-8 | Стек: React+Vite+TS / Fastify или FastAPI / Python-солвер / Postgres / pnpm-монорепо / docker-compose | Next.js, микросервисы, SQLite | Скорость вайбкодинга, шаринг типов, 3 движущихся сервиса максимум (`09` §2) | Принято | Если ≥2 бэкендеров за Python — FastAPI (уже допускается) |
| D-9 | Realtime: SSE (сервер→клиент), события версии плана | WebSocket, polling | Проще, автопереподключение, хватит для событий плана (`09` §2, `15` §2.3) | Принято | Если появится двусторонний стриминг (голос в реальном времени) |
| D-10 | Планы иммутабельны (версии + diff) | мутабельный текущий план | Бесплатные undo/история/диффы — питают UX перепланирования (`09` §6, `14` §2) | Принято | Никогда |
| D-11 | LLM: только текст↔структура (ввод заявки, полировка объяснений), поверх детерминированного ядра, с ручным фолбэком | LLM-агент диспетчер, нейро-солвер | Надёжность демо, честность, отвечаемость на вопросы жюри (`08` §4, §6) | Принято | Никогда (принцип); конкретные модели/провайдеры — свободно |
| D-12 | Голосовой ввод: локальный faster-whisper на нашем GPU | Web Speech API (облако), Vosk | Офлайн для сцены, точность на русском, GPU есть (`24` §1) | Принято | Если появится локальный ru-RU в Chrome on-device |
| D-13 | Демо-данные: fallback-датасет (генератор, фикс. seed) + адаптер под формат организаторов | ждать только их данные | Независимость от сроков/формата; репетируемое демо (`14` §5, `15` §1) | Принято | После получения реального формата — адаптер + сверка сценариев |
| D-14 | Уведомления: Telegram-бот как реальный канал, SMS — мок | SMS реальный, email | Бесплатно, интерактив (статусы), надёжно на сцене; SMS ~7 ₽/шт (`23` §1–2) | Принято | Если организаторы дадут SMS-шлюз |
| D-15 | Гео-слои города (работы/вода/погода) — выгрузка заранее, фича-флаги, подписи источников | живые запросы к порталам | Офлайн-гарантия демо; честность источника (`22` §6, `25` §3) | Принято | Никогда (правило демо-контура) |
| D-16 | Дизайн: светлая тема по умолчанию, MapLibre, фреймворк анимаций framer-motion, «Apple-подход» | тёмная по умолчанию, Leaflet | Диспетчер работает днём; полировка — наш главный козырь (`10` §1) | Принято | По ревью дизайнера на прототипах |
| D-17 | Не делаем: мобильное приложение, реальную интеграцию с CRM, регистрацию/роли, микросервисы, RL-солвер | — | Фокус на ТЗ + полировке; время хакатона (`12` анти-идеи, `08` §6) | Принято | Только явная просьба организаторов |
| D-18 | Расчётное ядро первично живёт в `core/` (корень репо) как day-0 прототип; целевой дом — `apps/solver` с layout `model/reasons/metrics/matrix`, который ядро уже соблюдает | сразу строить `apps/solver` + FastAPI-обёртку | Прямое решение тимлида: сначала подогнать OR-Tools-модель под кейс расчетно (детерминизм, причины, golden-гейт), API/контур потом; `core/solve.py` CLI самодостаточен на контракте `14` §3 | Принято | При создании скелета монорепо (`27` §1) код переносится в `apps/solver` без изменения контрактов, `core/` удаляется |

Как пользоваться: при споре «как сделать» — ищи D-№; если решения нет, предложи новую строку (ID, обоснование) тимлиду, после одобрения — внеси и действуй.
