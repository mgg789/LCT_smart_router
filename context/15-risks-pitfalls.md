# Риски, грабли и офлайн-план

> Назначение: типичные способы проиграть этот хакатон и их профилактика. Пройтись списком в день 0 и повторить накануне демо.

---

## 1. Продуктовые грабли (как теряют жюри)

| Риск | Профилактика |
|---|---|
| Демо-сценарий не отрепетирован: на сцене «а сейчас я покажу…» и ничего не работает | Репетиция ≥3 полных прогонов на той же машине (см. `13`) |
| Первое решение солвера долгое/недетерминированное | Прогреть солвер до сцены; фиксировать seed; лимит времени решения |
| План «пересобирается» по-разному на одинаковых данных — жюри заметит | Детерминизм: фикс. seed, фикс. порядок входов, время решения в кэш-нагрузке |
| Фича-полусловки: кнопка есть, результата нет | Правило «обещаем только то, что показываем»; чек-лист полировки `10` §7 |
| Импорт данных организаторов не работает на месте | Адаптер пишем в день 1 по реальному формату; fallback-датасет всегда с нами |
| Дедлайн-цейтнот выдавил полировку | План с буфером (`16`): полировка запланирована как отдельная задача, а не «если останется время» |

## 2. Технические грабли

### 2.1 Гео/карты
- **Геокодинг РФ ненадёжен** (корпуса, дроби, новостройки). Решение: демо-датасет прогеокодировать заранее, сложные адреса — вручную, рантайм — только кэш (`06` §5).
- **Тайлы карты:** публичные тайл-серверы (OSM) на сцене могут тормозить/палиться по ToS для прод-подачи. Решение: офлайн-векторный стиль города (plist/mbtiles) или растровые снапшоты как запаска; самохостинг тайлов — лучший вариант.
- **OSRM:** лимит `/table` 100 координат по умолчанию — поднять `--max-table-size`; данные РФ 3.9 ГБ — вырезать город заранее (`06` §3).
- **Пробки:** легальных потоковых данных РФ нет — time-dependent коэффициенты + честный ответ жюри (`06` §4, `13` §5).

### 2.2 Солвер
- Смешение «время в пути» и «сервисного времени» — учесть один раз в transit-callback (`05` §2).
- Slack в time dimension: 0 запрещает ожидания и ломает оптимальность с окнами — осознанно выбрать.
- Мягкие vs жёсткие окна: выбрать модель SLA сразу (жёсткое для VIP, мягкое с штрафом для остальных), не менять посреди разработки.
- «Инженер из дома» = мульти-депо: у каждого своя стартовая/конечная точка — не моделировать одним депо.
- Оборудование как «навык» (наличие комплекта у инженера) — достаточно для ТЗ; количественные лимиты — только если появятся в данных.

### 2.3 Архитектура
- Расхождение типов TS/Python из-за правок в трёх местах — один источник схемы (OpenAPI/zod), изменения контрактов — один человек (`09` §5).
- Realtime через WebSocket с ручным реконнектом — замена на SSE с автопереподключением (EventSource из коробки).
- Мутабельные планы «на месте» — теряется undo/история/диффы: только иммутабельные версии (`09` §6, `14` §2).
- Времена в разных зонах/форматах — всё в локальном времени города, единый формат ISO с оффсетом на входе, рендер на фронте.

## 3. Командные/процессные риски

| Риск | Профилактика |
|---|---|
| Вайбкодинг пяти человек разъезжается по стилям/контрактам | Контракты в день 0, CLAUDE.md/AGENTS.md с правилами, один владелец схемы, PR-минимум обсуждений |
| Дублирование работы (два пишут таймлайн) | Доска задач с владельцем и зоной (фронт/бэк/солвер/дизайн) — обновлять утром и после обеда |
| «У меня локально работает» | docker-compose целиком; смоук-тест `build plan → метрики` в CI/локально перед мержем |
| Дизайнер пришёл в конце | Дизайн-система (токены/компоненты) — в день 0, дальше дизайнер ревьюит сборки ежедневно |
| Перфекционизм на не-ядерных фичах | Скоуп-файл `12`: ядро/усилители/анти-идеи; новые идеи в хакатоне — только с одобрения тимлида |

## 4. Демо-инфраструктура: офлайн-план

1. Всё на ноутбуке: docker compose (api, solver, osrm, postgres, статика фронта). Проверено без Wi-Fi.
2. Кэш матриц и геокодов для демо-датасета — закоммичен в репо.
3. Тайлы: офлайн mbtiles города + запасной скриншотный режим карты (статичная картинка поверх, интеракции отключены) — на случай аварийного ноутбука.
4. LLM-фичи: локальный Qwen на своей машине; на сцене — либо локальный fallback-модель файл, либо режим «шаблонного ввода». LLM не должен быть на критическом пути демо.
5. Видео-бэкап демо + предзагруженные слайды локально (не из облака).

## 5. Мини-матрица «что убивает нас → кто страхует»

| Убивает | Страхует |
|---|---|
| Солвер завис/упал на сцене | `demo:reset` < 30 c; fallback жадный план; видео |
| Карта не грузится | Офлайн-тайлы; скриншотный режим |
| Формат данных организаторов неожиданный | Адаптер + fallback-датасет (демо не зависит от их файлов) |
| LLM не ответил | Ручная форма ввода; rule-based причины всегда |
| Интернет на сцене | Локальный стенд целиком |
| Спикер растерялся | Карточки-шпаргалки сценария; оператор ведёт по командам |
