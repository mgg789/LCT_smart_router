# Коммуникации: уведомления клиентам и инженерам (ресерч 2026-09)

> Фича-контекст: «диспетчер не должен звонить по каждому переносу». Сервис сам уведомляет: клиенту — «инженер приедет в 12:40, вот ссылка», инженеру — «план изменился». Здесь каналы (RU), цены, варианты реализации и что брать в демо.

|---|---|---|---|
| **Telegram-бот** | бесплатно, Bot API без лимитов практически | ⭐⭐⭐ для инженеров и B2B-клиентов: push, кнопки, ссылки, картинки (карта!) | **Основной канал демо** |

| WhatsApp/Viber API | недоступны/сложны для РФ | — | Нет |

## 2. SMS-агрегаторы РФ (для честного слайда «интеграция в prod»)

- **[SMSAero](https://smsaero.ru/price/sms/)** — без абонплаты; сервисные SMS от ~7 ₽/шт на больших объёмах, тестовые пакеты дешёвые; простой HTTP API.
- **[SMS.ru](https://sms.ru/api)** — API по HTTP/SMTP/email2sms, цены по операторам ([прайс](https://sms.ru/price)); есть готовые клиенты (Python `smsru-api` и др.).
- **МТС Exolve** ([тарифы](https://exolve.ru/tariffs/api/messengers/)) — API-платформа (SMS+голос+мессенджеры); с 13.10.2025 SMS на сеть Билайна 7,50 ₽; с 01.09.2026 — абонплата 1 220 ₽/мес за шаблон. Занятно для питча: «знаем стоимость SMS именно на сеть Билайн».
- Тренд 2025–2026: пакетная тарификация по уникальным абонентам, рекламные SMS дорожают — сервисные уведомления выгоднее проводить через мессенджеры.
- Вывод для продукта: интерфейс `NotificationChannel` с реализациями `telegram` (реально), `sms` (мок + лог), `email` (по желанию). Стоимость канала — аналитика «уведомления стоят X ₽/день» — приятная деталь продуманности.

## 3. Telegram-бот инженера (рекомендуемая реализация)

Возможности (все бесплатные):
- Карточка плана дня утром: список визитов с адресами, окнами, комплектом; кнопка «Открыть маршрут» (deep-link на мобильный вид продукта).
- **Push при перепланировании:** «Ваш день изменился: +заявка в 14:10, −заявка на Юге» — прямой мостик к нашей дельта-фиче (`07`).
- Статусы от инженера кнопками: «Выехал / На месте / Выполнено» → события в симулятор дня (двусторонняя связь!).
- Реализация: python-aiogram или node telegraf; webhooks для прода, polling для демо; токен — секрет в .env.
- В демо: телефон с Telegram на подиуме — инженер «подтверждает выезд» → статус на карте меняется. Живой двусторонний сценарий сильнее односторонних уведомлений.

## 4. Клиентский статус «инженер в пути» (публичная страница)

- Публичная read-only ссылка (токен в URL): карта с машиной (симуляция), ETA, окно, ФИО инженера, кнопка «Перенести» (открывает заявку на перенос).
- Реализация: обычная страница продукта `/track/{token}` — без нового стека; токены одноразовые с истечением (приватность).
- Это закрытие реальной боли «когда будет мастер?» и готовый ответ жюри на «а клиент что видит?».

## 5. Матрица уведомлений (правила продукта)

| Событие | Кому | Канал | Текст-пример |
|---|---|---|---|
| План построен | инженерам | Telegram | «План дня: 8 визитов, старт 9:20» |
| Перепланирование | затронутым инженерам и клиентам | Telegram / SMS | «Время визита сдвинулось на 20 мин» |
| Инженер выехал | клиенту | ссылка-страница | «Инженер выехал, ETA 12:40» |
| Риск опоздания > 15 мин | клиенту + диспетчеру | все активные | «Извините, приедем к 14:20» (прозрачность!) |
| Перенос по погоде/отключению | клиенту | Telegram/SMS | «В доме отключение воды 12–15ч, предлагаем завтра 10:00» |
| Обед/заправка | инженеру | Telegram | «Рекомендуем обед в 13:10, „Кофемания" в 300 м» |

Правило продукта: **уведомление = объяснённое изменение** (`11`), никогда не «молчаливый сдвиг». Шаблоны хранятся рядом с кодами факторов.
