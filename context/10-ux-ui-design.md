# UX/UI: диспетчерская консоль уровня Apple

> Назначение: главный козырь команды по стратегии — не «много фич», а «идеально продуманный инструмент». Здесь: принципы, инвентарь экранов, детальные спецификации ключевых экранов, карта, движение, чек-лист полировки. Дизайнер — владелец файла; разработчики — исполнители его решений.

---

## 1. Принципы (наша интерпретация Apple Human Interface для диспетчера)

1. **Clarity — ясность.** План дня читается за 3 секунды: кто, куда, когда, что рискует сорваться. Каждый пиксель информации конкурирует — оставляем только то, что меняет решение диспетчера.
2. **Deference — содержимое важнее хрома.** Минимум рамок и кнопок: карта и таймлайн — герои экрана. Панели всплывают поверх, а не режут рабочую область.
3. **Depth — глубина.** Иерархия: обзор → инженер → визит → причина. Каждое раскрытие — плавная анимация и сохранение контекста (никаких «улетел на другую страницу»).
4. **Доверие через предсказуемость.** Система ничего не меняет молча: любое авто-действие сопровождается диффом и объяснением. Отсюда — спокойствие диспетчера.
5. **Скорость = ощущение.** Всё < 100 мс отклик; оптимизация явно помечена прогрессом («пересобираю план…»), а не зависанием.

Визуальный язык: светлая тема по умолчанию (диспетчер работает днём), тёмная — переключатель; типографика Inter/«Golos Text» (кириллица!) — одна семья, шкала размеров 12/13/15/17/22/28; нейтральная палитра + 4 семантических цвета (SLA-риск красный/янтарный, успех зелёный, акцент — синий Билайна); радиусы 8–12; тени мягкие, двухслойные; сетка 4pt.

## 2. Инвентарь экранов (всего 4 + 2 вторичных)

| Экран | Роль | Приоритет |
|---|---|---|
| **1. Диспетчерский день** (главный) | Карта + таймлайн + панель деталей. 90% времени | P0 |
| **2. Заявка** (панель/модал) | Детали заявки, причины назначения, история, действия | P0 |
| **3. План/метрики** | Сводка плана: SLA, загрузка, пробег, сравнение версий | P0 |
| **4. Импорт/данные** | Загрузка датасета ТЗ, статусы геокодирования | P1 |
| 5. Инженер | Карточка: график, навыки, комплект, план дня | P1 |
| 6. Симуляция дня | Панель «time scrubber» + сценарии событий для демо | P1 (демо-киллер) |

**Не делаем:** настройки профиля, регистрацию, справочники с CRUD-таблицами (только просмотр), мессенджер, мобильную версию диспетчера.

## 3. Главный экран — спецификация

Лэйаут: слева **навигационная колонка 280px** (список инженеров с мини-статусами), центр — **карта**, справа/снизу — **таймлайн**, поверх — панель деталей. Коммутация: всё связано hover/click-синхронизацией.

### 3.1 Таймлайн (по инженерам, вертикальный)
- Строки = инженеры (аватар/инициалы, статус-точка: свободен/в пути/на объекте/перегружен).
- Ось X = время дня (8:00–19:00), плотная сетка часов.
- Визит = блок с адресом/типом работ, цвет по статусу SLA (нормально / риск / нарушено), «хвост» = переезд (блок-связка с временем дороги).
- Окно заявки — подложка-полоса за блоком (окно шире работы — видно запас).
- **Drag&drop**: перетаскивание визита между инженерами/по времени — с призрачным превью «что изменится» (пунктирный план до отпуска кнопки; отпускание → пересчёт → дельта-подсветка).
- Зум: колесо/щипок по оси времени; двойной клик по визиту — панель заявки.

### 3.2 Карта (MapLibre GL)
- Базовый слой: векторный светлайт-стиль (custom: приглушённые дороги, крупный город читается) — стилизуем под продукт, НЕ дефолтный яркий стиль.
- Маршруты: полилиния с «подложкой» (casing) белого/тёмного цвета под цветом линии; цвет = инженер; стрелки направления через symbol layer; hover по таймлайну → соответствующий отрезок маршрута утолщается.
- Маркеры визитов: номер в маршруте, форма по статусу, кластеризация НЕ нужна (масштаб города), коллизии подписей выключить.
- Окно заявки: при выборе — сектор/пульс вокруг точки? (дешевле: подсветка маркера + время в подписи).
- Событие перепланирования: старые маршруты растворяются, новые прорисовываются анимацией линии (draw-path animation), изменившиеся маркеры подпрыгивают. Никаких мгновенных перерисовок.

### 3.3 Панель деталей (справа, поверх карты, glassmorphism-lite)
- Выбранная заявка: заголовок (тип работ), адрес, окно, длительность, клиент, требуемые навыки/оборудование, инженер + время приезда, **блок «Почему так»** (см. `11-explainability.md`), действия (перенести, снять с плана).
- Выбранный инженер: загрузка дня (полоса), маршрут списком с временами, метрики (в пути X мин, простой Y мин).

### 3.4 Верхняя полоса (единственная)
- Дата-навигация, счётчики (заявки/риски/инженеры), кнопка **«Пересобрать план»**, переключатель авто/ручного режима, поиск (⌘K), симуляция дня.

### 3.5 Живая лента событий (правый нижний угол, коллапсируемая)
- «11:42 · Новая срочная заявка (клиент „Атлас") → план пересобран за 0.7 c · показ изменений».
- Каждый пункт разворачивается в дифф. Это же место покажет жюри п.4 ТЗ без лишнего клика.

## 4. UX перепланирования (киллер-фича, спецификация)

1. Событие → бейдж «Пересборка…» с прогрессом (0.5–2 c).
2. Готово: **карточка дельты**: «2 заявки переданы, 3 сдвинуты на ≤25 мин, риски SLA: было 2 → стало 1».
3. Кнопки: «Принять» (по умолчанию авто через 10 с) / «Отменить» (вернуть прошлую версию — планы иммутабельны, это просто указатель).
4. На карте/таймлайне изменённые элементы подсвечены до следующего действия.
5. Авто-режим vs полу-авто: настройка одним переключателем; в полу-авто дельта требует подтверждения. Для демо — авто (магия), для честности — показать оба.

## 5. Движение (motion) — правила

- Длительности: 120–180 мс (hover, панели), 250–350 мс (появление/маршруты), 400–600 мс (перепланирование) — плавные spring (framer-motion).
- Все переходы — по оси смысла: панель выезжает из той стороны, где её вызвали; маркер «подпрыгивает» там, где произошло событие.
- Скелетоны вместо спиннеров; спиннер допустим только на кнопке оптимизации.
- `prefers-reduced-motion` уважать (и это плюс в презентации).

## 6. Пустые состояния, ошибки, края

- Нет плана: иллюстрация + одна кнопка «Построить план» (первый вау-момент: секунда — и день распланирован).
- Заявку невозможно запланировать (нет инженера с навыком): не прятать — карточка «Нельзя запланировать» с конкретной причиной.
- Геокод не найден: бейдж на заявке + панель с ручным вводом координат.
- Ошибка сети/солвера: тост с действием «Повторить», никогда — белый экран.

## 7. Чек-лист «Apple-quality» перед демо (пройтись за час до сдачи)

- [ ] Ни одного дефолтного титула браузера, favicon, заглушки «lorem», битых иконок.
- [ ] Все даты/времена в одном формате; числа с пробелами-разделителями.
- [ ] Фокус-стили доступны с клавиатуры; Enter в формах делает ожидаемое.
- [ ] Hover-состояния у всех кликабельных; курсоры правильные.
- [ ] Анимации не блокируют повторные клики; двойной клик нигде не ломает состояние.
- [ ] Пустые состояния показаны хотя бы раз (в демо — специально показать не страшно).
- [ ] Скроллбары стилизованы; ни одного горизонтального скролла на главном экране.
- [ ] Заголовок/описание/мета — продукт выглядит «упакованным» (это замечают).

## 8. Референсы для дизайнера

- Apple HIG (модуальность, материалы), Apple Maps (стиль карты и маркеров).
- Linear (плотность, клавиатура, полировка), Cron/Notion Calendar (таймлайн-взаимодействия), Uber/Lyft dashboards (live-статусы), Google Maps Timeline (лента дня).
- Существующие FSM (см. `03-analogs-market.md`) — как НЕ надо: перегруженные таблицы, серые корпоративные UI.
