# Технические остановки: заправки, очереди на АЗС, парковки, отдых (ресерч 2026-09)

> Фича-контекст: инженер в фургоне весь день — ему нужны обед, туалет, дозаправка, парковка у объекта. Продукт, который сам втыкает «человеческие» остановки в маршрут и объясняет где — это вау-фича заботы о пользователе. Здесь: источники данных по Москве и варианты реализации.

---

## 1. Дозаправка и очереди на АЗС

### 1.1 Публичного API очередей нет — это факт
Проверено: очередь/загруженность АЗС показывают потребительские сервисы, но ни один не даёт API:
- **Яндекс Карты/Навигатор** (июль 2026) показывают в карточке АЗС очереди и наличие топлива — данные из «Яндекс Пробок», отчётов водителей ([ТАСС](https://tass.ru/ekonomika/27899331), [новость Яндекса](https://yandex.ru/company/news/17-07-2026-01), [Expert.ru](https://expert.ru/news/yandeks-nachal-pokazyvat-nalichie-ocheredey-na-azs-v-moskve-i-peterburge)). API нет.
- **«АЗС ЛУКОЙЛ»** — карта АЗС с наличием топлива в приложении ([инструкция](https://licard.ru/ru/News/News/proverte-nalichie-topliva-v-mobilnom-prilozhenii)); **Газпромнефть** — [карта АЗС](https://gpnbonus.ru/fuel/refuel-map) и приложение АЗС.GO. API нет.
- Краудсорс-сервис «ГдеБЕНЗ» — отметки водителей, API нет.

### 1.2 Что берём: данные точек + эвристика очереди + deep-link
- **Точки АЗС:** OSM через Overpass (`amenity=fuel`, теги `brand`, `opening_hours`, `fuel:diesel`) — компактная выгрузка по Москве один раз и кэш (рецепт ниже). Точность покрытия Москвы хорошая.
- **Эвристика загруженности:** по часам (пик ~8–10 и 17–19) и типу АЗС; помечаем «ожидается очередь ~N мин» в подсказке. Честная подпись «оценка, не факт».
- **Deep-link на Яндекс Карты** с фактической очередью: `https://yandex.ru/maps/?text=АЗС%20%brand%&...` — диспетчер одним кликом видит реальную очередь (данные недоступны API, но ссылка легальна и полезна).

### 1.3 Варианты реализации фичи «дозаправка»
1. **Виртуальная заявка «дозаправка»** (рекомендация): если остаток пробега < 15% дня — солвер вставляет 15-минутную остановку на ближайшую к маршруту АЗС. В OR-Tools моделируется как обычный визит с `allowed_vehicles=[этот инженер]`.
2. **Пассивная подсказка:** на таймлайне маркер «низкий топливный прогноз — предложи заправку» + кнопка «вставить в маршрут» (лучше для демо: человек видит заботу).
3. В карточке остановки: время, бренд, адрес, ссылка на Яндекс Карты (очередь), отклонение от маршрута (+N мин).

## 2. Обед и отдых (главная «человеческая» фича)

- Норматив: ТК РФ — перерыв для отдыха и питания 30–120 мин (в рабочее время не включается); для профессиональных водителей — режимы отдыха по приказу Минтранса. Для демо достаточно: «обед 45 мин в интервале 12:00–14:30».
- **Модель в солвере:** OR-Tools поддерживает **breaks** нативно: `routing.SetBreakIntervalsOfVehicle(...)` — интервал, когда транспортное средство «не едет» (пример Vehicle Breaks в официальных docs). Break вставляется в свободное между окнами место — то, что нужно.
- **Где обедать:** Overpass (`amenity=cafe|fast_food|restaurant`, `amenity=toilets`, парки `leisure=park`) — выбор точки в радиусе 300 м от места, где инженер окажется в обеденном окне. UI: «Обед у Иванова 13:10–13:55 · «Кофемания» на Ленина · +2 мин от маршрута».
- Вариант проще: обед «на месте» (в машине/у клиента) без геопривязки — дефолт, если кафе не найдено.

## 3. Парковка у объекта (боль для фургонов в Москве)

- **data.mos.ru** — портал открытых данных с [API](https://data.mos.ru/developers/documentation): формат `https://apidata.mos.ru/v1/datasets/{id}/rows?api_key={key}` (ключ бесплатный по регистрации). Релевантные наборы: [«Парковки» (№623)](https://data.mos.ru/opendata/623) — округ/район/адрес/кол-во мест; «Городские плоскостные автостоянки»; «Зоны платной городской парковки» (архивная копия с полями — [DataCrafter](https://data.apicrafter.ru/packages/datamos-paidparkingzones)); перехватывающие парковки. Карты наборов с координатами — проверять паспорт конкретного набора при скачивании.
- Официальный сервис города: [parking.mos.ru](https://parking.mos.ru/) (~178 тыс. мест на уличных платных).
- **Фича:** карточка визита «Где встать»: ближайшие парковочные объекты (из data.mos.ru + OSM `amenity=parking`/`parking_space`, с фильтром «влезет фургон»), предупреждение «зона платной парковки, тариф ~X ₽/ч».
- Вариант реализации: в выгрузку с координатами точек добавляем `parking_hint` (текст + 2–3 ближайших объекта); сложный вариант — учёт стоимости парковки в стоимости визита.

## 4. Электрозарядные станции (задел под EV-флот)

- На data.mos.ru существует набор **«Зарядные станции для электромобилей»** (координаты, типы разъёмов) — подтверждено [архивной копией DataCrafter](https://data.apicrafter.ru/packages/datamos-chargingelectricstations); в живом каталоге искать «зарядные станции».
- Вариант фичи: если парк гибридный (в данных ТЗ — класс ТС), планировщик для EV-инженера строит маршрут с учётом остатка заряда и вставляет 30-мин зарядку на ЭЗС (моделирование как «заправка» из §1.3). Это «next-level» фича — берем только если парк EV появится в данных организаторов или как what-if демонстрация.

## 5. Overpass API: практический рецепт (кэшируем один раз)

```overpassql
[out:json][timeout:60];
(
  node["amenity"="fuel"](55.45,37.2,55.95,37.95);
  node["amenity"="charging_station"](55.45,37.2,55.95,37.95);
  node["amenity"~"cafe|fast_food|restaurant"](55.45,37.2,55.95,37.95);
  node["amenity"="toilets"](55.45,37.2,55.95,37.95);
  node["amenity"="parking"](55.45,37.2,55.95,37.95);
);
out body;
```
- Bbox = юг,запад,север,восток (примерно Москва); интерактивно — [Overpass Turbo](https://overpass-turbo.eu/); эндпоинты `overpass-api.de` / `kumi.systems`; лимитеры — ставить `timeout` разумно, публичный сервер не грузить ([примеры](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_API_by_Example), [документация bbox](https://dev.overpass-api.de/overpass-doc/en/full_data/bbox.html), [рецепты на Python](https://janakiev.com/blog/openstreetmap-with-python-and-overpass-api/)).
- Процедура: выгрузка один раз до демо → в `data/aux/` (JSON) → продукт работает офлайн. Лицензия OSM: ODbL — атрибуция в футере карты.
