# Контекст проекта: сервис планирования маршрутов выездных инженеров (Билайн Бизнес, ЛЦТ 2026)

> Папка собрана до старта хакатона (этап разработки открывается 15 сентября 2026). Задача: веб-сервис интеллектуального планирования маршрутов выездных инженеров — распределение по квалификации, временные окна, транспорт/оборудование, SLA, авто-перепланирование, карта + объяснение причин.
>
> Стратегия команды: не «много фич», а максимально продуманное, целостное и красивое приложение (Apple-подход) с объяснимостью как ядром доверия.

## TL;DR решения (2 минуты)

- **Задача формально:** гетерогенная VRPTW с навыками, оборудованием и мульти-депо, динамическая, мульти-целевая (SLA > балансировка загрузки > время в пути).
- **Ядро:** OR-Tools (GLS) как оптимизационное ядро + собственный слой причин (rule-based объяснимость); Timefold — проверенная альтернатива; масштаб (20–100 заявок) решается за миллисекунды — побеждаем качеством модели и UX, а не скоростью.
- **Гео:** self-hosted OSRM (docker) для матрицы/маршрутов, геокодирование демо-датасета заранее + кэш; пробки — честные time-dependent коэффициенты.
- **Киллеры:** панель «Почему так» с альтернативами и контрфактами; дельта-анимация перепланирования с откатом; симулятор дня для живого демо; what-if сравнение «жадный vs оптимизатор».
- **AI:** LLM только для естественного ввода заявки и полировки объяснений — поверх детерминированного ядра, с ручным фолбэком; нейрокомбинаторика/RL — осознанно не берём (умеем объяснить почему).
- **Стек:** React+TS+Vite+MapLibre+Tailwind / FastAPI или Fastify / Python+OR-Tools / PostgreSQL / docker-compose, всё офлайн-способно.

## Быстрый вход для агента

1. `26-case-source.md` (ТЗ дословно) → `00-README` TL;DR → `01-task-analysis` → `16-stack-and-plan` → файлы своей зоны (карта в `28-agent-bootstrap` §3).
2. Правила работы: готовый `AGENTS.md` в `28-agent-bootstrap.md` §2 — скопировать в корень репозитория.
3. Решения не переоткрывать: `29-decision-log.md`.

## Как пользоваться

1. **Перед стартом (сейчас):** прочитать `01`, `17`, `16` — общая картина; владельцы зон — свои файлы.
2. **В день открытия ТЗ:** сверить `01` с реальным ТЗ и датасетами; задать вопросы из `01` §8 и `17` §7.
3. **В работе:** файлы — источники решений; при расхождении реальности с контекстом — обновить файл (контекст живой).
4. **Накануне демо:** `13` + `15` + чек-листы из `10` §7.

## Глоссарий (коротко)

- **VRP/VRPTW** — Vehicle Routing Problem (with Time Windows); **SLA** — обещанный уровень сервиса (окно/время); **LNS/ALNS/GLS** — семейства эвристик улучшения плана; **Warm start** — старт оптимизации с предыдущего плана; **Дельта-дифф** — набор изменений между версиями плана; **Explainability** — объяснимость решений; **Seed** — фиксируемая randomness для воспроизводимости демо.
