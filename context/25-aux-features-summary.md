## 2. Как это подаётся в демо (сценарий `13` обновление)

Вспомогательные фичи не вставляются в основной сценарий подряд — они раскладываются по нему точками доказательства:
- Основной сценарий (`13` §2) остаётся.
- **Точка 1 (доверие к городу):** после построения плана — панель «Дорожные работы» и «Отключение воды» (2 адреса подсвечены) → «сервис знает о городе».
- **Точка 2 (забота):** таймлайн показывает авто-обед с кафе у маршрута и подсказку заправки → «сервис заботится об инженере».
- **Точка 3 (живая связь):** телефон-в Telegram: инженер «Выехал» → статус на карте; клиентская ссылка «инженер в пути» показывается на втором экране/телефоне.
- **Точка 4 (голос):** срочная заявка диктуется голосом → парсинг → подтверждение → перепланирование (сливается с главным wow-моментом).
- В Q&A-заготовки добавить: «Сколько стоят уведомления?» (§ SMS-цены), «Почему не Яндекс API для трафика?» (легальность, `20` §3).

## 3. Порядок внедрения (после ядра MVP, см. `16` §4)

1. Погода + производственный календарь (XS–S, влияние на данные).
2. Подложка/тайлы (S — нужно для карты в любом случае, выбрать основную).
3. Страница «инженер в пути» (S).
4. Telegram-бот (S–M).
5. Дорожные работы + отключения воды (S–M, слои данных).
6. Авто-обед (M — требует breaks в солвере).
7. 2GIS ETA-переключатель (S–M, если демо-ключ).
8. Голосовой ввод (S–M).
9. PDF/.ics (S–M).
10. Парковки/дозаправка подсказки (S).

Правило: каждая фича — за фича-флагом, с офлайн-данными и подписью источника; если фича не готова к концу Х2 — она молча отключается флагом и остаётся roadmap-слайдом.
