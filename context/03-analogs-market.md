# Аналоги и рынок FSM / маршрутизации (ресерч для ЛЦТ)

> Назначение: подсмотреть паттерны у лидеров рынка и найти white space — то, чего нигде нет, что станет нашим дифференциатором. Ресерч 2026-09: международные и российские продукты.

## 1. Карта рынка

| Категория | Примеры | Логика |
|---|---|---|
| Enterprise FSM | Salesforce Field Service, ServiceNow FSM, IFS FSM | Управление сервисной организацией целиком: наряды, ресурсы, SLA-контракты, инвентарь |
| Routing-first SaaS | Route4Me, OptimoRoute, Routific, WorkWave, Onfleet, Tookan | Ядро — оптимизация маршрутов + диспетчерская панель |
| SMB field service | Jobber, Housecall Pro, Workiz, Skedulo, Praxedo, ServiceM8 | Клиенты/наряды/оплаты для малых сервисных компаний |
| Российские FSM/логистика | Планадо, ШЕДЕКС, Маппа, Logist Uno, Телетрек, ANTOR RouteMaster, Hubex, Veeroute, Яндекс Маршрутизация | Локализация, 1С/Битрикс24, работа в РФ |
| Open source | Fleetbase (logistics platform), Traccar (трекинг) | Основа/референс для своих решений |

## 3. Глубокие разборы (наиболее релевантные)

### Route4Me — «наворочено, но не любя»
Ядро: оптимизация + мобильные приложения. Для полевых услуг заявляет routing по «proximity, skill set, и equipment» — ровно наша предметная область, значит функционал такого рода рыночно востребован. Dynamic re-optimization — кнопка «Optimize» перестраивает день. Вывод: наша задача — показать то же самое, но (а) для российских данных, (б) с объяснением каждого решения, (в) в UI, в котором приятно работать.

### OptimoRoute — лучший таймлайн-диспатчинг
Drag&drop заказа между маршрутами прямо на таймлайне + «Best fit» (система сама подбирает позицию). Мультидневное планирование. Это ближайший референс для нашего таймлайна: мы добавляем к DnD предпросмотр последствий (что меняется) и объяснение отказов — этого у них нет.

### Salesforce Field Service — модель навыков
Ресурсы с skills/certifications, приоритизация по SLA-контрактам, scheduling-политика. Отсюда берём лексику и структуру данных (skill→work type), но не UI.

### Планадо — российский контекст
Проверенный продукт для мобильных бригад (поверители, монтажники): электронные наряды, назначение на карте, офлайн-приложение, интеграции с 1С/Битрикс24. Важный урок: русскоязычная терминология и интеграции решают при внедрении. Для жюри от Билайна полезно позиционироваться «не ещё одно Планадо», а «оптимизационно-объясняющее ядро, которого нет ни у кого на рынке РФ».

## 4. Паттерны, которые есть у всех (де-факто стандарт)

1. Диспетчерская = **карта + расписание/таймлайн + список заказов**, синхронизированные выделения.
2. **Drag&drop** назначения/перестановки, с «best fit»-подсказками.
3. Статусы заказа/исполнителя цветом; **live-трекинг** исполнителей.
4. Мобильное приложение исполнителя: маршрут дня, наряд, чек-листы, отметка выполнения.
5. Уведомления клиентам о времени визита.
6. API/интеграции (CRM, ERP) — отдельная ось ценности.

## 5. White space — чего нигде нет (наши возможности)

1. **Объяснимость решений (L1/L2/L3)** — ни один продукт не показывает «почему эта заявка у этого инженера» с факторами и альтернативами. У нас это п.5 ТЗ — делаем первоклассно (`11`).
2. **Дельта-перепланирование как UX-событие** — при изменениях плана все либо молча переписывают день, либо требуют полного ручного вмешательства. Карточка дельты + анимация + авто-откат — наша фишка (`07` §7).
3. **Стабильность плана** как настраиваемый вес («не перетряхивай день») — не встречается в SaaS.
4. **What-if сравнения планов** (веса критериев, «жадный диспетчер» vs оптимизатор) — отсутствует у всех; для жюри — визуальная демонстрация ценности.
5. **Естественно-языковой ввод заявки** — на рынке РФ почти нигде; безопасно строится поверх ядра (`08` §4).
6. **Русскоязычный продукт уровня полировки Linear/Apple** — рынок РФ в этой нише преимущественно «корпоративно-серый».

## 6. Выводы для проекта (берём/не берём)

- **Берём паттерн:** карта+таймлайн+список с синхронизацией; DnD с best-fit; статусы цветом; лента событий.
- **Улучшаем:** каждый DnD — с предпросмотром последствий; каждая автозамена — с дельтой и причиной.
- **Изобретаем:** объяснимость (L1–L3), what-if, «жадный режим» для сравнения, стабильность как вес.
- **Не берём:** электронные наряды/чек-листы/оплаты (не про ТЗ), мультидневное планирование (фокус — день), CRM-интеграции (roadmap-слайд), мобильное приложение исполнителя (только превью-вид).
- **Позиционирование для питча:** «рынок умеет возить поезда и курьеров; мы — первая система для выездных инженеров, которая объясняет свои решения и не перетряхивает план без причины».
