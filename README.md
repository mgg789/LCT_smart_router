# Navix Router

**V1.0** (2026-09-21). Рабочий контур: дашборд диспетчера, приложение инженера,
клиентский контур (API + письма), System Layer, Router Core, официальный датасет
205/35. Публичный стенд: <https://navix.droidje.com>. Что вошло и чего сознательно
нет: [docs/release-v1.0.md](docs/release-v1.0.md) (история —
[docs/release-v0.1.md](docs/release-v0.1.md)). Видео и скриншоты демо — в
[`demo/`](demo/README.md).

Веб-сервис интеллектуального планирования и оперативного перепланирования маршрутов
выездных инженеров. Кейс «Билайн Бизнес» (номинация «Логистика»), ЛЦТ 2026.

Идея продукта — не «много фич», а один продуманный инструмент, которому диспетчер
доверяет: **план за секунды → карта с маршрутами → объяснение каждого решения
человеческим языком → наглядное перепланирование при изменениях дня → сравнение
с базовым планированием по обязательным метрикам**.

> Публичный стенд: [navix.droidje.com](https://navix.droidje.com)

Вход диспетчера на этом стенде (ТЗ логин не требовал — это защита контура;
пароль здесь, потому что жюри должно зайти без отдельной переписки):

## Быстрый запуск

Требуется Docker (с плагином `docker compose`) и pnpm 10. Node 24 LTS нужен только
для запуска вне Docker и для тестов.

```bash
git clone <этот репозиторий> && cd LCT
cp .env.example .env        # обязательно: задать DISPATCHER_EMAIL и DISPATCHER_PASSWORD
pnpm install
pnpm compose:up             # postgres + миграции + router core + api + web
```

Поднимаются пять сервисов:


|Сервис|Адрес|Что это|
|:---|:---|:---|
|Dashboard|<http://127.0.0.1:5173>|Витрина диспетчера (карта, план, политики)|
|API|<http://127.0.0.1:8000/docs>|System Layer (NestJS), интерактивная документация|
|Router Core|<http://127.0.0.1:8100>|Расчётное ядро (Python \+ OR-Tools), приватный API|
|PostgreSQL|127\.0.0.1:5432|Бизнес-данные и опубликованные снимки задачи|

Дальше — только UI (пошагово: [docs/tz-acceptance.md](docs/tz-acceptance.md)):

1. Войти диспетчером (на публичном стенде — учётка выше; локально — из `.env`).
   На экране входа можно открыть автономный демо-сценарий без датасета ТЗ.
2. Сайдбар **+** → **«Использовать датасет из ТЗ»**. Подгружаются три региона из
   репозитория (205 заявок / 35 инженеров). План считается сам, отдельной кнопки
   «Построить план» нет.
3. Семь шагов ТЗ кликаются подряд: карта и список → таймлайн инженера → карточка
   заявки → вкладка **«Инженеры»**, выключить человека с линии → новый план с
   дельтой → вкладка **«Политики»**, строка **«Базовая из ТЗ»**.

`pnpm smoke` — сквозная проверка контура с нуля. Деструктивна, только на своей
машине.

Запуск без Docker и диагностика — [docs/runbook.md](docs/runbook.md).

## Семь шагов ТЗ в интерфейсе

Полный клик-гайд и честная сверка «пункт ТЗ → что есть / чего нет»:
[docs/tz-acceptance.md](docs/tz-acceptance.md).

|Шаг ТЗ|Куда нажать|Что увидите|
|:---|:---|:---|
|1. Загрузка данных|Сайдбар **+** → **«Использовать датасет из ТЗ»**|205 заявок / 35 инженеров из репо, план применяется сам|
|2. Распределение|Вкладка **«План дня»**, список слева|Кто сколько заявок взял; навыки и доступность режет алгоритм|
|3. Порядок адресов|Клик по инженеру|Таймлайн под картой|
|4. Карта|Центр «Плана дня»|Точки и маршруты. Восток — OSRM; Юго-восток/Юго-центр — центроиды|
|5. Кто / куда / когда|Клик по заявке|Правая карточка: адрес, окно, исполнитель|
|6. Событие дня|**«Инженеры»** → выключить «На линии»|План без этого человека, плашка «переданы / сдвинуты»|
|7. Объяснение|Карточка заявки|«Почему этот инженер» или «Почему без назначения»|

Срочной заявки и отмены кнопками нет. Событие для проверки перестроения — отключить
инженера. Базовый FIFO из ТЗ не выбирается как политика: он выделен песочной строкой
**«сравнение с ТЗ»** на вкладке «Политики».

**Ограничения алгоритма (не декларация):** навык заявки ∈ навыки инженера; работа +
дорога в смене, старт внутри окна; транспорт совпадает, *если в заявке указан*
(в официальном CSV поле пустое).

## Как это устроено

```text
Dashboard (apps/web)  ──►  System Layer (apps/api)  ──►  PostgreSQL
                                  │  ▲                     │
                      снимок задачи│  │ результат           │
                                  ▼  │ (5 проверок)        ▼
                         Router Core (core/, Python + OR-Tools) ◄── читает снимок
```

- **System Layer** (`apps/api`, NestJS 11 \+ Prisma \+ PostgreSQL) владеет бизнес-состоянием:
  заявки, инженеры, факты выполнения, журнал операций с идемпотентностью. По каждому
  значимому событию публикует **целый снимок оставшейся задачи** с hash; принимает
  результат ядра только после пяти независимых проверок (режим AUTO/MANUAL, hash снимка,
  версия контекста, пригодность плана, отсутствие конфликта с фактами).
- **Router Core** (`core/`, Python \+ OR-Tools 9.15) — автономный сервис: строгий контракт
  снимка/результата, точный FIFO-baseline в каждом расчёте, тёплый старт при
  перепланировании, объясняющие факторы для каждого назначения. Детерминизм закреплён
  golden-тестами.
- **Dashboard** (`apps/web`, React \+ TypeScript \+ Vite \+ Tailwind \+ MapLibre) — витрина
  диспетчера: карта, таймлайны, карточки с объяснениями, сравнение политик, список
  инженеров с включением/выключением, утренний список оборудования по бригадам (n\+1),
  управление API-токенами. В том же приложении живёт **SPA инженера** (`/engineer/`):
  план дня, отметки визитов, обед и техперерыв, вход по email-коду.

Подробности: [docs/architecture.md](docs/architecture.md) (слои и блоки),
[docs/api.md](docs/api.md) (контракты API), [docs/data.md](docs/data.md) (модель данных),
[docs/solver.md](docs/solver.md) (алгоритм), [core/README.md](core/README.md) (ядро).

## Алгоритм

- **Политики оптимизации.** Иерархию целей задаёт выбранная политика; по умолчанию —
  `compact`: сначала максимум выполненных заявок, затем минимум задействованных
  исполнителей, далее пробег. Пресеты: `fast`, `sla`, `balanced`, `eco`,
  `covering` (compact на штатном составе, затем хвост закрывают синтезированные
  смены `covering-*`). Резерв живёт только в покрывающей политике: в compact/fast/
  sla/eco/FIFO и в таблице сравнения его нет, иначе все стратегии схлопываются.
  FIFO из ТЗ — не пресет, а строка сравнения на вкладке «Политики». Первое
  сравнение после публикации может занять до ~90 с (бюджет 8 с на стратегию).
- **Перепланирование в UI.** Событие, которое можно нажать: инженер недоступен
  (вкладка «Инженеры», снять «На линии»). Срочная заявка и отмена в интерфейсе
  не выведены. Режим «Вручную» в шапке переключается; жестов перетаскивания
  назначения нет.
- **Оборудование** (роутер / приставка / колонка / ничего): утром бригада видит список
  оборудования по своим заявкам с одним запасным комплектом (n\+1); в v0 инженеры
  оборудование не обменивают. Потребность заявки учитывается при планировании.
- **Обеды** по умолчанию выключены (как и в задаче организаторов); включаются
  переключателем в дашборде — планирование при этом честно учитывает окно и длительность.
- **Объяснения** — структурированные, из данных решателя: соответствие навыка, запас
  по окну, добавленная дорога, альтернативы и причины отказа кандидатов; у неназначенной
  заявки — человеческая причина (нет навыка / нет транспорта / не помещается в окно
  или смену).

## Данные и допущения

Официальный датасет организаторов (`data/dataset/anonymized/`, кодировка cp1251,
разделитель `;`): **205 заявок** на один рабочий день 17.08.2026 в трёх независимых
регионах (Восток — 66, Юго-восток — 83, Юго-центр — 56) \+ контрольное распределение
по бригадам. В каждом файле скрыта строка «Адрес Офиса» — точка старта всех бригад
региона; возврат в конце дня не требуется.

Чего в датасете нет — синтезируем сами (ТЗ прямо это разрешает, при фиксации допущений):


|Пробел|Наше решение|
|:---|:---|
|Справочник инженеров|Бригады контрольного распределения (11–12 на регион); навыки и транспорт — детерминированное правило, все 3 навыка и 4 типа транспорта представлены|
|Длительности работ|Четыре профиля норм по типам работ (подключение / авария / дозаказ / локальная); переход на официальные нормативы — правка конфигурации|
|Приоритет|«Авария», «Нет линка» → Срочная (выполняется как можно раньше), остальное — Обычная|
|Координаты|Версионированные геокод-пакеты `data/dataset/geocoded/<регион>.json`; точки заявок — задекларированные проекции по центроидам районов|

Явные допущения: бригада = один исполнитель; пробег считается по дорожному графу
(для Юго-востока пока аппроксимация «гаверсинус × 1.25, 28 км/ч» — см. «Ограничения»);
парковка и пропуска включены в время дороги; начать работы до открытия окна нельзя,
позже внутри окна — допустимо; заявки с окном «весь день» планируются на весь горизонт.

## Стек и стороннее ПО


|Слой|Технологии|
|:---|:---|
|Frontend|React 19, TypeScript (strict), Vite, Tailwind, MapLibre GL, framer-motion|
|Backend|NestJS 11, Node 24 LTS, Prisma ORM, PostgreSQL 17 (\+pgvector про запас), Zod|
|Ядро|Python 3.14, Google OR-Tools 9.15 (Routing), собственные граф и матрицы дорог|
|Инфраструктура|pnpm workspaces, docker compose (5 сервисов), node:test / pytest / vitest|

Почему так: OR-Tools назван в ТЗ рекомендованной технологией и закрывает VRPTW
«из коробки»; MapLibre — открытая карта без платных ключей (геокодеры OSM разрешены
организаторами); PostgreSQL — единое хранилище и бизнес-данных, и снимков задачи.
AI/LLM в расчёте не участвует — решение осознанное: детерминизм и проверяемость важнее.

```text

apps/api          — System Layer (NestJS): API, операции, снимки, приёмка результатов
core/             — Router Core (Python + OR-Tools): движок, runtime, гео-ресурсы

infra/            — docker-compose локального и демо-контура

context/          — рабочие записи команды: ТЗ, QA-сессия с организаторами, решения
```

## Известные ограничения и планы

- Дорожная матрица Юго-востока — детерминированная аппроксимация (заявлено выше);
  следующий шаг — реальные дорожные времена (OSRM) для всех регионов.
- Длительности работ — наши профили норм; при получении официальных нормативов
  от организаторов обновляются одной правкой конфигурации.
- AI-контур заявлен в архитектуре, но сознательно не включён
  (`/health/services` честно сообщает `not_configured`); SMTP-контур работает.
- Кнопок срочной заявки и ручного перетаскивания назначений в дашборде нет;
  событие дня для проверки — отключить инженера.
- Дорожная карта: AI-ввод заявки и агенты, живая картина дня на карте диспетчера,
  официальные нормативы, реальные дорожные матрицы для всех регионов.
