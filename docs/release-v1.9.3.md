# Navix 1.9.3

Релиз объединяет изменения `dev` по `f07951a` после опубликованного `v1.7`.
Незавершённые ветки и открытые PR в него не включены.

## Что изменилось

- Локальные лаунчеры показывают коды входа без SMTP для диспетчера, инженера
  и клиента. Сохранённые и импортированные настройки не отключают демо-коды.
  Обновлены проверки целостности, восстановления установки и документация.
- Добавлены Route Engine 3 и необязательный кэш Redis-beta; настройки и границы
  применения описаны в `docs/route3.md` и `docs/redis-beta.md`.
- Для точек вне дорожного графа сохранены явные приближённые прямые; проверяются
  времена и концы выбранных плеч. Исправлены ожидания между плечами и связность
  геометрии метро. Графы не расширялись: прямые не подтверждают наличие дороги.
  Условия и изменившиеся результаты планирования приведены в
  `docs/benchmarks/routing-outside-20260929/README.md`.
- Обновлены графики работы инженеров, завершение рабочего дня, загрузка именованных
  наборов данных, экспорт плана, обработка времени и окна аварийных заявок.
- Включены новые таблицы организаторов с геокодами, исправления интерфейсов
  диспетчера, инженера и клиента, а также обновления AI-объяснений и чатов.
- Закрыт неавторизованный доступ к включённым метрикам API и Router. Для включения
  метрик нужны отдельные токены сборщика; секреты не входят в пакет.
- Документация сверена с реализацией; удалён устаревший каталог `context/`.
- Экспорт каталога работ для Python синхронизирован с API, включая дополнительные
  названия проблем ТВ и роутера. Предрелизные проверки исправлены: unit coverage
  получает собственное окружение и запускает тесты также в Windows; погодный
  интеграционный тест учитывает дату окончания визита при переходе через полночь.

## Обновление

Нужно применить миграции `20260929170000_shift_pattern` и
`20260929180000_fit_outage_windows`: первая добавляет график работы инженера,
вторая расширяет слишком короткие окна ещё не начатых аварийных заявок.
Перед миграцией сохраняются БД, приватная конфигурация и прежние образы.

Публичный сервер сохраняет `NODE_ENV=production`, `AUTH_DEV_EXPOSE_CODES=false`
и существующую доставку кодов по SMTP. Локальный пакет использует отдельный
режим демо-входа; его настройки не переносятся на production.

Лаунчер не обновляет себя автоматически. Для новой установки скачайте исходный
архив `v1.9.3` со страницы релиза. Возможности платформ и результаты предыдущей
проверки лаунчера описаны в `docs/launcher-validation.md`.
