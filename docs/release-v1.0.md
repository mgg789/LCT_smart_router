# V1.0 — что выпускаем

Статус на **2026-09-21** (релизный гейт 03:30 МСК). Прирост относительно
[V0.1](./release-v0.1.md); базовые сценарии дашборда не менялись. Публичный стенд:
<https://navix.droidje.com>. Локально: `pnpm compose:up` → <http://127.0.0.1:5173>.

## Что вошло после V0.1

**Приложение инженера** (`apps/web` SPA `/engineer/`, вход по email-коду):

- план дня и маршрут, карточки точек, отметки визитов (`выехал → на объекте →
  начал → завершил`, плюс «проблема» и «приехал, не может начать»);
- обед с фактическим временем, техперерыв, выход на линию/офлайн;
- превышения длительности: подтверждённый финиш отпускает инженера раньше,
  материальное отклонение возвращает маршрут в перепланирование;
- сессии бригады на 30 дней, настройка имени/транспорта/почты.

**Инженер ↔ логин.** Диспетчер выдаёт бригаде адрес (`link-account`) и снимает его
(`unlink-account`); роль инженера предоставляется только диспетчером, не экраном входа.

**Авторизация по email.** Одноразовые коды входа для клиента и инженера, диспетчер —
код или пароль. Коды не логируются; `devCode` в ответах только при
`AUTH_DEV_EXPOSE_CODES=true` (демо-контур), в `production` сочетание запрещено схемой
окружения.

**Внешний программный доступ.** API-токены трёх категорий (`client`, `eng`,
`client_eng`) + `master`, хэши в БД, срок действия, панель выпуска/отзыва в настройках
дашборда. Интеграционный ключ называет объект по `clientEmail`/`engineerId`/id заявки;
гайд: [integration-guide.md](./integration-guide.md).

**Почтовый контур.** Внешний SMTP (Postfix за Hysteria, watchdog, fallback-транспорт):
очередь интентов с дедупликацией по бизнес-переходу, отправка `nodemailer`, контроль
на `accepted_by_server`. Каталог писем доведён до всех видимых переходов заявки
(принята → назначена → мастер приступил → выполнена / отменена / согласовать время /
время изменено) и итогов дня инженеру; шаблоны — светлая и тёмная темы по макетам
Figma. Адрес может отключить письма-события; код входа не отключаем. Отмена заявки и
настройка тишины — клиентские эндпоинты (`docs/api.md` §5).

**Роутер.** Отправление с учётом фактов (`departure-aware`), цели политик и полное
покрытие (`!22`), покрывающие маршруты и дополнительный состав, сохранение транспортных
профилей при недоступности дорожных провайдеров.

**Релизный регресс-гейт** (DRO-81): изолированный контур с нуля — smoke, API,
браузерные сценарии, потеря связи, отзыв сессии, интеграционный ключ, мобильный
инженер, остановка/восстановление Router ([ci.md](./ci.md)).

## Чего в V1.0 нет — нарочно

- **AI-gateway** (`not_configured` в `/health/services`): чаты, AI-объяснения,
  агенты клиента/инженера/диспетчера — следующий релиз.
- **Клиентское приложение как UI** — не в теге; клиентский контур полностью доступен
  по API и через письма (гайд выше).
- **Живая картина дня диспетчера** (фактический прогресс по маршруту на карте,
  вечерний отчёт дня) — работа ведётся в отдельной ветке, в тег не входит.
- Кнопки «срочная заявка» и ручного перетаскивания назначений в дашборде по-прежнему
  нет; событие для проверки перестроения — снять инженера с линии.
