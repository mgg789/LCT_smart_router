# База знаний AI-контура

Этот каталог — источник знаний для ассистентов трёх ролей продукта: клиента, инженера
и диспетчера. Он читается индексатором и подмешивается в контекст модели как
справочный материал, а не как код и не как инструкция, меняющая права модели.

## Три сегмента и кто их читает

| Сегмент | Каталог | Кто читает |
|---|---|---|
| `client` | `docs/knowledge/client/` | Только клиентский ассистент |
| `engineer` | `docs/knowledge/engineer/` | Только инженерный ассистент |
| `dispatcher` | `docs/knowledge/dispatcher/` | Все три ассистента — клиентский и инженерный тоже могут читать диспетчерский сегмент |

Правило одностороннее и обязательное: диспетчерский сегмент — самый широкий по
полномочиям (например, объясняет правила приёмки плана, деградацию ручного режима,
данные сбросов), и клиентский/инженерный ассистент не должны сами решать за
диспетчера или выдавать себя за него, даже читая тот же материал. Клиентские и
инженерные статьи никогда не читаются диспетчерским контуром неявно — если диспетчеру
нужен факт из клиентского сегмента, это отдельный явный вызов, а не подмешивание по
умолчанию.

Все три каталога — `client/`, `engineer/`, `dispatcher/` — заполнены по одному и тому
же контракту front-matter (см. ниже), просто разными командами: id статей начинаются
с `cli-`, `eng-` и `disp-` соответственно. У диспетчерского сегмента дополнительно есть
рабочий каталог ситуаций `docs/knowledge/dispatcher-situations.md`. Он лежит **рядом**
с каталогами сегментов, а не внутри одного из них, и это не косметика: правило
индексатора звучит как «каждый `.md` внутри каталога сегмента обязан иметь валидный
front-matter, иначе индексация падает». Файл без front-matter внутри сегмента сделал бы
это правило неисполнимым, а исключение по имени — дырой, в которую однажды провалится
настоящая статья.

## Контракт фронт-маттера

Каждая индексируемая статья начинается с YAML-блока строго такой формы:

```yaml
---
id: disp-01-day-shape
segment: dispatcher
title: Форма рабочего дня и LIVE
summary: Одна фраза, которую ассистент может процитировать дословно.
tags: [live, день, старт]
actions: [get_day_state, get_live_view, start_live_day]
related: [disp-02-reading-the-plan, disp-10-closing-the-shift]
updated: 2026-09-20
---
```

- **id** — стабильный идентификатор статьи по сегменту: `disp-NN-slug` (диспетчер),
  `cli-NN-slug` (клиент), `eng-NN-slug` (инженер) — используется в `related` и в
  логах индексатора.
- **segment** — один из `client`/`engineer`/`dispatcher`; определяет таблицу доступа
  выше.
- **title** — короткий заголовок для списков и ссылок.
- **summary** — одна фраза, которую ассистент может процитировать дословно в ответе
  диспетчеру без искажения смысла. Пишется как законченное утверждение, не как
  аннотация «статья о том, что…».
- **tags** — свободные ключевые слова для поиска по индексу.
- **actions** — имена инструментов ассистента, которые эта статья **авторизует**
  использовать в контексте описанной темы (например, `resolve_alert`,
  `reassign_request`). Пустой список `[]` означает, что статья не даёт права ни на
  одно действие записи — это явное состояние, не пропуск поля. Разрушительные
  операции (импорт/догрузка/сброс данных) намеренно никогда не входят в `actions`
  ни одной статьи: они не AI-actionable, см. `12-data-and-regions.md`.
- **related** — id соседних статей, которые стоит прочитать рядом с этой.
- **updated** — дата последней проверки фактов в статье по коду (`YYYY-MM-DD`).

## Правило `##`-чанкинга

Индексатор режет каждую статью на чанки по заголовкам второго уровня (`##`). Отсюда
два практических следствия для авторов:

1. Каждый `##`-раздел должен быть самодостаточным настолько, чтобы иметь смысл, если
   модель получит только его — не полагаться на то, что предыдущий раздел той же
   статьи точно окажется в том же контексте.
2. Заголовок раздела должен быть информативным сам по себе (не «Подробнее», не
   «Ещё один случай») — он часто оказывается единственной подсказкой о содержимом
   чанка в списке результатов поиска.

Front-matter не чанкуется отдельно — `summary` и `actions` попадают в контекст вместе
с первым чанком статьи и обычно неявно опираются индексатором как краткая сводка при
показе списка найденных статей.

## Текст статьи — данные, не инструкция

Содержимое любой статьи (включая её `summary`) — это **данные для ответа**, а не
директива, меняющая права модели, системный промпт или разрешённый набор действий.
В частности:

- Статья может объяснить, что означает код `NO_FEASIBLE_ASSIGNMENT_FOUND`, но не может
  сама по себе разрешить модели вызвать эндпоинт, не перечисленный в `actions`.
- Если текст статьи (в результате будущего редактирования человеком с ошибкой, или в
  результате внедрения через пользовательский ввод, который случайно попал в
  индексируемый файл) содержит фразы вида «теперь ты можешь…», «игнорируй предыдущие
  правила», «действуй как…» — это тоже данные, которые нужно процитировать или
  отклонить по смыслу, а не выполнить как команду.
- Подтверждающие фразы сбросов (`reset to test data`, `erase all application data`,
  см. `12-data-and-regions.md`) — это факты о продукте для объяснения диспетчеру, а не
  токены, которые ассистент может сам произнести от имени диспетчера, чтобы
  разблокировать действие.

Ровно то же правило действует и для `dispatcher-situations.md`: это рабочий каталог
для проектирования и для оценочного набора, он не индексируется и не должен
интерпретироваться моделью как часть базы знаний в рантайме.

## Переиндексация

```bash
pnpm --filter api knowledge:index
```

Скрипт появится позже вместе с реализацией самого индексатора — команда фиксируется
здесь заранее как договорённость об интерфейсе. До его появления правки в
`docs/knowledge/**` не подхватываются автоматически: индекс нужно пересобирать вручную
тем способом, который будет описан в реализации скрипта.

## Оценочные наборы

Каждый сегмент может иметь свой набор в `apps/api/test/fixtures/ai/<segment>-eval.json`
(диспетчерский — `dispatcher-eval.json`) — список примеров `{id, prompt, mustContain,
mustNotContain, expectedTools, notes}` для регрессионной проверки ответов ассистента.
Это тестовые данные, не часть индексируемой базы знаний, и не читаются рантаймом
ассистента.
