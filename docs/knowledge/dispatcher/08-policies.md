## Общий блок покрытия для всех

`core/policy.py` компилирует для каждой политики строгий лексикографический порядок
критериев. Первые четыре — общий блок покрытия, одинаковый для всех шести: срочные
неназначенные заявки, все неназначенные заявки, пропущенные необязательные обеды,
суммарное опоздание. Только после того, как этот блок не может быть улучшен, каждая
политика жмёт свой собственный хвост целей.

## Чем платит каждая политика

| Политика | Хвост после покрытия |
|---|---|
| `fast` | время в пути → пробег → число инженеров |
| `compact` (по умолчанию) | число инженеров → пробег → время в пути |
| `sla` | риск окна (минимальный запас до исходного закрытия) → время в пути → пробег → число инженеров |
| `balanced` | максимальная доля занятой смены → разброс загрузки в секундах → время в пути → пробег → число инженеров |
| `eco` | пробег → число инженеров → время в пути |
| `covering` | дополнительные региональные инженеры → число инженеров → пробег → время в пути |

`balanced` считает загрузку как занятый размах (работа + дорога + ожидание + обед) —
это минимакс загрузки, не стандартное отклонение; в разброс включаются и свободные
инженеры. По умолчанию используется `compact` — так решено по итогам QA, и на ней
собраны основные сценарии и golden-эталоны.

## Covering — отдельный случай

`covering` не просто переставляет приоритеты — она может **добавлять** дополнительные
региональные бригады сверх исходного состава, чтобы повысить покрытие. Она не гарантирует
минимальность добавленного состава и не назначает физически недостижимые окна: часть
заявок всё равно может остаться неназначенной. Именно поэтому её маршруты не входят в
основную таблицу сравнения из шести строк — они несравнимы по составу с остальными
политиками и FIFO-базой; число добавленных бригад передаётся отдельно
(`additionalEngineers`), седьмой строкой.

## Как сравнивать и когда переключать

`GET /dispatch/policy-comparison` считает все политики и FIFO-`baseline` на **текущей
опубликованной задаче** — тяжёлый эндпоинт (бюджет по умолчанию 8000 мс на стратегию;
первый ответ после публикации может идти до ~90 с). Возможны 503 (обычный пересчёт ещё
не закончился) и 409 `VERSION_CONFLICT` (данные изменились за время расчёта) — оба
означают «переспросить позже», не ошибку ввода; не дёргать эндпоинт в цикле. Смена
политики (`POST /dispatch/policy`) — это холодный старт: память прежнего расчёта не
переносится, публикуется новая задача, и план на экране сменится не мгновенно, а после
приёмки нового результата. Нет редактора формул, весов или порядка критериев — только
выбор из шести готовых пресетов.
