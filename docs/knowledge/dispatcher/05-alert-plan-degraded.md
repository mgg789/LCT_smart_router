## Как считается деградация ручного плана

Пока применённый план — ручной (`plan.origin='manual'`), sys периодически прогоняет его
через `POST /v1/manual-evaluation` Router: порядок визитов переоценивается на актуальном
снимке и текущей политике **тем же расчётом стоимости**, что использует оптимизатор —
маршрут не оптимизируется и не применяется автоматически, только оценивается. Результат
несёт `feasible`, `degraded`, `criterion` (конкретный критерий, по которому план хуже),
`before`/`after` (лексикографические векторы) и кэшируется по ревизии плана, хешу входа
и версии контекста Router.

## plan_degraded vs plan_review_required

Если оценка посчиталась и `degraded=true` — алерт `plan_degraded`, с текстом вида
«Ручной план хуже автоматического по критерию «⟨…⟩» политики «⟨…⟩»» и человекочитаемым
именем критерия (срочные неназначенные, неназначенные, пропущенные необязательные обеды,
время в пути, дорога, число инженеров, дополнительные инженеры, риск окна, суммарное
опоздание, загрузка, разброс загрузки). Если оценка недоступна (например, Router
временно не отвечает) — вместо недоказанного утверждения о деградации появляется
`plan_review_required` с явным текстом «Оценка ручного плана временно недоступна.
Проверьте решение вручную или восстановите автоматический вариант». Это разные по силе
утверждения: не подменять одно другим.

## keep_manual и restore_auto

Оба кода разрешают ровно два действия. `keep_manual` требует непустую `reason` —
сервер отклонит вызов без неё (`VALIDATION_FAILED`); диспетчер фиксирует, что осознанно
остаётся на ручном плане, несмотря на предупреждение. `restore_auto` возвращает режим
в `auto`, если у Router есть готовый (`status='ready'`) результат на текущий
опубликованный `input_hash` — иначе `VALIDATION_FAILED` с просьбой повторить, когда
Router будет готов.

## restore_auto не закрывает алерт мгновенно

После выбора `restore_auto` алерт остаётся **открытым**: сервер применяет ещё пригодный
результат уже после коммита операции, и алерт снимается только тогда, когда план
фактически стал `origin='auto'` при следующей проверке. Ассистент не должен сообщать
«готово» сразу после отправки решения — корректная формулировка: «переключение
запрошено, алерт закроется, когда автоматический план реально применится».
