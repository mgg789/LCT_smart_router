# Аудит документации — 29.09.2026

Задача: DRO-145 «Финализировать документацию». Исходная база — `dev`,
commit `a136b259601cdfb7adb0a2071e2378b8711e8fb8`; рабочая ветка —
`docs/repository-audit`. После обнаруженного падения E2E пользователь отдельно
разрешил обновить браузерные тесты под текущий интерфейс и повторить регрессию.

## Объём и способ проверки

Инвентаризация исходной базы: **1736 отслеживаемых файлов**, из них **160 Markdown**.
Автоматический проход проверил локальные ссылки и якоря всех Markdown, включая
архивы, ссылки на исходники, команды package scripts и упоминания HTTP-маршрутов.
Для контрактов использованы 157 операций сгенерированного OpenAPI, контроллеры,
Zod-схемы, общие wire-типы, Pydantic-настройки и Prisma/SQL-миграции.

| Область | Что сверялось |
|---|---|
| Корень, `context/` | Онбординг, карта знаний, ADR, статус концепций, отличие старых снимков от реализации |
| `apps/api`, `packages/shared` | Авторизация, health, профили/смены, HTTP, операции, LIVE, асинхронная геометрия, AI-инструменты |
| `apps/web`, `tests/e2e` | Три ролевых интерфейса, доступные подписи, настройки, вход, сессия, карта и действующие проверки |
| `core/`, `data/`, `lab/` | CLI, бюджеты, строгие окна, политики, provenance, геокоды, golden и сохранённые бенчмарки |
| `services/` | Road API, Route Engine 3, System one и отдельная выдача установки; topology Compose и конфигурационные входы |
| `infra/`, `scripts/`, `launch/` | Compose, профили, CI, изолированные тесты, лаунчер, миграции, порты и подготовка запуска |
| `docs/knowledge`, `docs/manuals`, `demo/`, `apps/promo` | Доступ к знаниям, индексируемые статьи, HTML/PDF, датированные записи и документация съёмки |

Это аудит соответствия документации исходникам и проверенным сценариям.
Автоматическое чтение всех файлов не означает построчную проверку каждого
алгоритма, безопасность всего кода или повторную валидацию всех внешних исследований.
Исходные PDF/QA организаторов, архивы и сохранённые результаты не переписывались
как будто они получены на новой версии.

## Границы результата

Параллельный чат «Изучи проект и создай дизайн» работал над 2ГИС в отдельном
worktree; его checkout переключал основную ветку без изменения базового HEAD.
Регрессии двух чатов пересекались на одном Docker Desktop, но использовали разные
Compose-проекты/БД. Причинная связь нагрузки со сбоем seed не установлена.
29.09 правки этого аудита перенесены в собственный managed worktree, 38 файлов
проверены по SHA-256 до очистки основной рабочей копии. `dev` в основной папке чист;
последующий прогон выполняется после перехода второго чата в ожидание.

- Production, серверные настройки и релизная ветка `main` этим проходом не меняются.
- Доставка SMTP в конечные ящики и настоящий LLM/System one не проверялись.
- Внешние исследовательские ссылки/утверждения старого контекста не получили
  массовой повторной интернет-валидации. Даты и статус исторических источников сохранены.
- Не вводились новые HTTP/DTO/SQL-контракты; `packages/shared` не редактировался.
  Raw evidence не объявлено новым обязательным публичным endpoint.
- Браузерный regression использует штатный Playwright проекта: Browser plugin
  с отдельным `browser` skill в сессии не доступен. Проверки не заменяют все
  пользовательские маршруты, ОС/браузеры, нагрузочный тест или приёмку production.
