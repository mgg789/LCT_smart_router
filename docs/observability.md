# Метрики, трассировка и ошибки

Три независимых механизма включаются явно через env. Без них API, Router и браузер
запускаются штатно; отключённые SDK не инициализируются и не отправляют данные.
Prometheus и Collector — дополнительные сервисы Compose, Sentry подключается к внешнему
проекту по DSN. Собственный сервер Sentry этот репозиторий не разворачивает.

## Настройки

| Компонент | Метрики | Трассы | Ошибки |
| --- | --- | --- | --- |
| API | `METRICS_ENABLED` | `OTEL_ENABLED` | `SENTRY_ENABLED` |
| Router | `ROUTER_METRICS_ENABLED` | `ROUTER_OTEL_ENABLED` | `ROUTER_SENTRY_ENABLED` |
| Браузер | — | — | `VITE_SENTRY_ENABLED` |

Все флаги по умолчанию `false`, для включения используйте `true`.
`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` и `ROUTER_OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`
содержат полный HTTP endpoint OTLP, включая `/v1/traces`. В Compose по умолчанию это
`http://otel-collector:4318/v1/traces`. Для запуска процессов на хосте задайте доступный
им endpoint; порт Collector наружу не опубликован. Доля корневых трасс задаётся через
`OTEL_TRACE_SAMPLE_RATIO` / `ROUTER_OTEL_TRACE_SAMPLE_RATIO` от 0 до 1 (по умолчанию 0.1).
Родительское решение sampling сохраняется, API передаёт trace context в приватный Router.

Для Sentry нужны `SENTRY_DSN`, `ROUTER_SENTRY_DSN`, `VITE_SENTRY_DSN` соответствующих
проектов. `SENTRY_ENVIRONMENT` и `SENTRY_RELEASE` в Compose передаются всем трём
компонентам; для самостоятельного запуска Router используются `ROUTER_SENTRY_ENVIRONMENT`
и `ROUTER_SENTRY_RELEASE`, для браузера — соответствующие `VITE_` переменные.
Браузерные настройки встраиваются при **сборке**: изменение env требует пересборки web.
DSN браузерного проекта публичен по назначению; Sentry auth token в `VITE_` не помещают.

## Запуск сервисов

Задайте нужные флаги в `.env`, затем:

```sh
docker compose --env-file .env -f infra/docker-compose.yml --profile observability up -d --build
```

Альтернатива параметру — `COMPOSE_PROFILES=observability` в окружении. Профиль запускает
Prometheus и Collector, но сам по себе не включает SDK: их флаги независимы.
Обычный запуск без профиля не создаёт дополнительные сервисы. Уже запущенные сервисы
профиля при смене флагов автоматически не останавливаются; остановите их адресно:

```sh
docker compose --env-file .env -f infra/docker-compose.yml stop prometheus otel-collector
```

Prometheus доступен только на `127.0.0.1:9090` (порт меняется через `PROMETHEUS_PORT`),
хранит данные в отдельном томе до 7 дней / 1 GB. Конфигурация опрашивает `/metrics`
API и Router каждые 15 секунд. Выключенный endpoint возвращает 404, поэтому отключённая
цель будет отображаться как DOWN — это не отказ самого приложения. Endpoint предназначен
для приватной сети, без прикладной авторизации; не публикуйте его через внешний ingress.

Collector принимает OTLP/HTTP и в поставляемой конфигурации выводит краткую диагностику
пакетов через `debug` exporter. Это проверка приёма, **не долговременное хранилище трасс**.
Для поиска трасс подключите в `infra/observability/otel-collector.yml` exporter своего
OTLP-совместимого хранилища. Лимит памяти Collector — 128 MiB, отправка пакетная.

## Что собирается

- API: процессные метрики и гистограмма `lct_api_http_request_duration_seconds` с
  количеством запросов; Router: `router_http_requests_total` и длительность запросов.
- Метки HTTP: метод, **шаблон** маршрута, статус. Неизвестные пути объединяются в
  `unmatched`; ID заявок и параметры URL не создают отдельные серии.
- Трассы: входящие HTTP API/Router и клиентский запрос API → Router. Автоматического
  перехвата SQL, LLM, геокодинга и внешних URL нет. Тела, query, cookies, authorization
  и baggage не экспортируются.
- Sentry: серверные ошибки и сбои отображения/необработанные ошибки браузера.
  Тексты исключений и содержимое запросов исключены; автоматические интеграции,
  запись сессий и replay отключены. Это не сбор пользовательской аналитики.

Экспорт идёт ограниченными пакетами и с таймаутами; очереди сбрасываются при корректном
завершении серверных процессов. Недоступность приёмника не должна блокировать запросы.
Некорректная конфигурация включённого API SDK останавливает запуск; Router и браузер
отказываются от недоступного экспортера и продолжают работу. Валидируйте подключение
после включения, а не только наличие переменных.

## Проверки

`apps/api/test/observability.test.ts` проверяет off-режим, endpoint метрик, ограниченные
метки и доставку OTLP/Sentry в локальные HTTP-приёмники. `core/tests/test_observability.py`
проверяет Router; frontend-тесты — ленивую загрузку, отключение и очистку события.
Эти проверки не заменяют проверку доступа и приёма событий в выбранном внешнем Sentry.
