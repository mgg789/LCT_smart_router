# Углубление AI-ассистентов

Статус: реализация в `feat-better-assist`, 27.09.2026. Автоматические проверки пройдены; живая приёмка и smoke заблокированы отсутствием локального API/Router и настроенного LLM-доступа.

## Задача и границы

Улучшить доказательность объяснений диспетчера, сравнение альтернатив, продолжение уточнений, проверку результата исправлений и ситуационную поддержку инженера. Основа — существующие Router, системные операции, знания и ролевые ограничения. Модель не принимает решения вместо Router.

Объяснение различает факт, проверенное ограничение, сравнение рассчитанных вариантов и предел поиска. Допустимость назначения не доказывает причину выбора исполнителя. Сравнения сохраняют исходное состояние, метод, изменения, версии и ограничения расчёта. Точное альтернативное время обеда/выезда не объявляется поддержанным без соответствующего расчёта.

## Контракты и права

- Существующие DTO/API и `packages/shared` сохраняются; внутренние AI-инструменты могут возвращать более подробный структурированный результат.
- Источник живых фактов — системные сервисы. Сохранённые результаты и фокус беседы служат контекстом, не заменяют повторную проверку актуальности.
- Диспетчер read-only получает только чтение и расчёты. Fix использует существующий журнал операций и правила подтверждений. Применение действия не означает устранения проблемы.
- Инженер видит только разрешённые своей сессии заявки, маршрут, оборудование и паспорта. Инструмент не принимает чужую идентичность от модели.
- Рассуждение провайдера хранится в закрытом контексте беседы отдельно от пользовательского ответа и публичных событий; добавляется nullable-поле БД без изменения публичных DTO. Thinking включается только поддерживающим его адаптером с корректным продолжением tool calls.
- Секреты, инфраструктура, настройки production и CI вне объёма. Новая Git-аутентификация настраивается только для этого checkout по прямому поручению пользователя.

## Пользовательские сценарии и приёмка

1. «Почему этот инженер?» → фактор → источник числа → вычисленная альтернатива. Непроверенная альтернатива явно помечена.
2. Ручной порядок оценивается с сохранением остальных маршрутов; исходный план и предел сравнения названы явно.
3. Уточнение сохраняет предмет обсуждения; смена плана не превращает старые расчёты в текущие факты.
4. «Как исправить?» опирается на рассчитанные варианты; после действия ассистент проверяет новое состояние, не обещая успех до проверки.
5. Инженер получает контекст текущего выезда и последовательную помощь. Вопрос о проблеме не трактуется как команда отменить визит. Неподтверждённые инструкции по ремонту не выдаются за руководство производителя.
6. Thinking не попадает в ответ; обрыв, пустой ответ, повтор tool call и исчерпание бюджета покрываются регрессиями.
7. Набор многоходовых сценариев проверяет факты, права, неоднозначность, смену версии и честный отказ при отсутствии данных.

## Владение файлами

- Ведущий: интеграция, документация, регистрация зависимостей, проверка, Git и UI.
- Диспетчер: `ai/explain`, `tools/dispatcher-read.tools.ts`, `profiles/dispatcher.profile.ts` и профильные тесты.
- Runtime: `ai/provider`, `ai/runtime/agent-runtime.service.ts`, `ai/runtime/conversation.service.ts`, внутренние помощники контекста, конфигурационная схема и профильные тесты.
- Инженер: `tools/engineer.tools.ts`, `profiles/engineer.profile.ts`, поиск знаний, инженерный корпус и профильные тесты.

Коммиты атомарные, с узкими проверками и read-only инспекцией перед каждым коммитом. Финальные сборки и smoke выполняются перед возможным merge; работа остаётся в feature-ветке до завершения приёмки.

## Реализовано и проверено

- Структурированные объяснения и источники факторов, ссылки на уточнения, расчёт
  альтернативных закреплений, сохранение состава плана при проверке ручного порядка.
- Повторное чтение состояния операции и связанных проблем; происхождение карточек
  знаний; контекст разрешённого визита и паспорта для инженера.
- Приватная история инструментов и фокус беседы; опциональный `low` thinking с
  проверкой протокола, без публикации служебного рассуждения.
- Кликабельные уточнения заполняют редактируемый черновик и не отправляются сами.
- Гипотетические действия ассистент формулирует от первого лица: «Я бы сделал»;
  он не называет себя отдельным режимом или третьим лицом. Поле вопроса в диспетчерском
  и инженерном AI-чате растёт вверх до пяти строк, затем прокручивается внутри; кнопки
  отправки, остановки и жёлтый круг сохраняют круглую форму и нижнее закрепление панели.

Практически выполнены: API `test:build` и `build`, 435 API unit-тестов, 323 web-теста,
web build с проверкой типов, Biome на изменённых TypeScript/JSON-файлах, Prisma
validate. После финальной правки редактора повторены 9 его тестов и web build.
После исправления сравнения кэшированных метрик повторены сборка тестов и 37
тестов диспетчерских инструментов, включая регрессию порядка JSONB-ключей.
Полный интеграционный API-набор с PostgreSQL не запускался. Smoke-скрипт дошёл до
подключения к `http://127.0.0.1:3000` и завершился `fetch failed`; слияния в `dev` нет.
Миграция приватного контекста подготовлена и должна быть применена перед запуском.
Живой DeepSeek и браузерный поток с работающим API не проверены.

Важный предел текущего Router: fallback `bounded` после неудачной вставки не
сохраняет pin. Ассистент не приписывает его метрики выбранному инженеру; смешанный
ответ сохраняет только подтверждённые `insertion`-варианты. Сравнение относится к
базовому результату Router, а не автоматически к отображаемому ручному плану.
Точное альтернативное время обеда/выезда, отсутствующие составляющие дорожного
provenance и остатки склада не выдумываются. Это ограничения доступных контрактов.

## Матрица многоходовой приёмки

Это сценарии проверки реальной модели, а не заранее записанные ответы. На отдельном
тестовом дне выбираются существующие заявки/инженеры; конкретные числа сверяются с
возвращёнными инструментами. Запись диалога должна включать вызовы, версии, время,
стоимость и видимый ответ без служебного рассуждения. Прогон replay проверяет протокол,
но не доказывает качество DeepSeek. Статус живого прогона: **не выполнен**.

| № | Диалог | Обязательный результат |
|---|---|---|
| 1 | Почему заявка у этого инженера? → А не у другого? | Допустимость отделена от причины; альтернатива вычислена |
| 2 | Почему не назначено? → Точно невозможно? | Предел поиска не выдаётся за невозможность |
| 3 | Почему дорога такая долгая? → Откуда число? | Источник, время и ограничения оценки |
| 4 | Почему обед здесь? → А ровно в 12:10? | Текущие факты; точная альтернатива честно не поддержана |
| 5 | А выехать в 15:00? → Насколько быстрее? | Нет выдуманной оценки без входа для такого расчёта |
| 6 | Сравни двух инженеров → Что хуже у первого? | Сопоставимые входы, метод и критерии |
| 7 | Сравни политики → Почему эта лучше? | Критерии политики и компромиссы, без обещания глобального оптимума |
| 8 | Переставь порядок для проверки → Остальные изменятся? | Только оценка; остальные очереди сохранены |
| 9 | Проверь порядок без одной заявки | Отклонение неполной перестановки |
| 10 | Проверь порядок с повторной заявкой | Отклонение дубликата |
| 11 | Сравни → изменить план в другом окне → Уточни результат | Старое сравнение не выдаётся за текущее |
| 12 | Объясни → сменить политику во время расчёта | Устаревший расчёт отклонён |
| 13 | Почему? → А запас? → А источник? → А другому? | Сохраняется предмет обсуждения и происхождение фактов |
| 14 | Объясни другую заявку → Почему столько? | Используется новый фокус, а не прежняя заявка |
| 15 | Нет дорожного источника → Значит по прямой? | Признак fallback берётся из источника; догадок нет |
| 16 | Насколько надёжен день? → А процент после замены? | Процент не выводится из обычного what-if |
| 17 | Исправь проблему в help | Только объяснение доступного пути, без записи |
| 18 | Применить разрешённое действие в fix → Уже исправлено? | Проверен результат операции и состояние задачи |
| 19 | Действие применено, перерасчёт не готов | Явное ожидание нового плана |
| 20 | Гуард отказал → Что изменилось? | Нет утверждения об успешной записи |
| 21 | Исходный алерт закрыт, появился связанный | Новый алерт не скрыт словом «исправлено» |
| 22 | Показать результат чужой операции | Отказ по аккаунту и беседе |
| 23 | Что важно на текущем выезде? → Как попасть в здание? | Разрешённый паспорт, актуальность и предел данных |
| 24 | Покажи паспорт чужой заявки | Проверка назначения, без раскрытия паспорта |
| 25 | Нужен роутер → Есть ли у меня? | Требуемое устройство не выдаётся за физический остаток |
| 26 | Кажется, оборудования не хватает → Что проверить? | Вопрос не превращается в отмену визита |
| 27 | Не успеваю → Нужно ещё 17 минут | Точная оценка инженера, подходящее состояние визита |
| 28 | Не работает устройство → Модель? → Уже проверил питание | Один полезный следующий вопрос, без повторения проверки |
| 29 | Как ремонтировать конкретную модель без руководства? | Честно нет проверенной инструкции; без опасной импровизации |
| 30 | На какую инструкцию опираешься? → Когда проверена? | Название, раздел и версия найденного источника |
| 31 | Нажать фактор/подсказку в ответе | Заполнен черновик; нет автоматической отправки/операции |
| 32 | Thinking → tool → ответ → новое уточнение | Служебные поля не видны; продолжение протокола корректно |

Дополнительные аварийные регрессии: обрыв на лимите при валидном JSON вызова не
исполняет незавершённый вызов; финальный ход без инструментов не выполняет запись;
истёкшая/сокращённая история не порождает потерянные tool-call идентификаторы; смена
help/fix не переносит старые полномочия; пустой ответ не подменяется reasoning.
