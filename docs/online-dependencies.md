# Онлайн-зависимости и офлайн-режим

Контур спроектирован офлайн-first: **планирование, перепланирование, карта,
объяснения и метрики работают без интернета**. Всё, что ходит наружу, кэшируется
и деградирует по явно описанному пути. Этот документ — полный список функций,
требующих онлайна, и того, что каждая теряет при его отсутствии. Замер точности
офлайн-прогноза против онлайн-Яндекса: ±8% — [benchmarks/roads-vs-yandex](benchmarks/roads-vs-yandex-20260929/README.md).

## Внешние сервисы (интернет)

| Сервис | Зачем нужен | Когда требует онлайн | Поведение офлайн |
|---|---|---|---|
| **Open-Meteo** (`api.open-meteo.com`) | Погодный множитель времени в пути (дождь/снег/гроза) и подсказки инженеру | Периодические запросы прогноза; ответ кэшируется | Множитель = 1,0 (дороги без погодной надбавки), бейдж погоды не показывается |
| **2GIS Distance Matrix / Routing** | Точные матрицы времён и текущий трафик при наполнении кеша | Разовое наполнение кеша перед работой; вне compose | Кешированные матрицы или локальный дорожный граф; ошибка не кэшируется как «непроезжаемо» |
| **Nominatim** | Геокодирование новых адресов, которых нет в каталоге | Наполнение геокод-каталога | Офлайн-каталог `data/dataset/geocoded/*.json` (198 адресов официальных регионов); неизвестный адрес падает явно, а не угадывается |
| **Языковая модель** (OpenAI-совместимый провайдер / прокси OpenRouter) | AI-ассистенты, пересказ объяснений, оформление заявки свободным языком, System one по алертам | Каждое живое AI-обращение | `LLM_PROVIDER=off/replay`: детерминированные черновики и ручные объяснения; демо-режим полностью офлайн. LLM не участвует в планировании — на план его отсутствие не влияет |
| **SMTP-шлюз** | Письма с кодами подтверждения клиента | Регистрация/восстановление клиента | Вход по паролю от SMTP не зависит; шлюз без конфигурации честно сообщает `not_configured` |
| **Overpass / выгрузки OSM** | Сборка и обновление дорожных и пешеходных графов | Только подготовка данных (офлайн-шаг), не рантайм | В рантайме графы уже вендорены в репозиторий |

## Локальные сервисы контура (между контейнерами, не интернет)

| Сервис | Роль | Примечание |
|---|---|---|
| PostgreSQL | Хранение заявок, планов, ревизий, баллов | Требует запущенного контейнера |
| Redis | Кэш каталога/чтений | Опционален, есть fallback |
| `road-api` | Дорожный граф МКАД: геометрия плеч и пакетные времена | Наш сервис, вендоренный граф 167 МБ |
| `route-engine3` | Маршруты/матрицы по OSRM-графам, метро | Наш сервис, Apache 2.0 |
| OSRM-бэкенды | Локальные процессы `osrm-routed` | Поднимаются контейнерами, интернета не требуют |

## Что работает полностью офлайн

- Загрузка данных: официальный CSV-импорт (cp1251) и панель табличной загрузки
  с геокодированием из офлайн-каталога; демо-наборы `data/samples/`.
- **Планирование и перепланирование**: полный движок (ограничения, оптимизация,
  политики, обеды, handoffs, MANUAL-режим), латентность события — доли секунды.
- **Карта**: вендоренные графы дорог и метро, подложка всех официальных регионов,
  маршруты по улицам.
- **Объяснения и метрики**: структурные факты ядра, причины неназначения, сравнение
  с FIFO, риск-оценка Монте-Карло — всё считается локально.
- **История плана, откат, алерты** (детерминированные черновики), база знаний,
  баллы и PDF-отчёты, чаты (локальный бэкенд).

Именно офлайн-контур проверен бенчмарками: качество планов идентично на ноутбуке и
сервере, точность времени в пути — ±8% от онлайн-Яндекса, детерминизм
байт-в-байт между macOS и Linux.

## Что теряется без интернета (честный список)

1. Погодная надбавка ко времени — поездки оцениваются без дождя/снега (множитель 1,0).
2. Свежий трафик 2GIS сверх встроенного прогноза — работает калиброванный прогноз
   по времени выезда, но без текущих пробок «прямо сейчас».
3. Живые AI-ответы — формулировки становятся детерминированными шаблонами/replay.
4. Письменная доставка кодов подтверждения — клиентская регистрация по коду из
   письма требует SMTP-шлюза.
5. Геокодирование адресов вне каталога — новый адрес требует разового онлайн-шага
   или ручного ввода координат.

## Что требует онлайна функционально

- **Живые AI-функции** (ассистенты, свободный язык, AI-объяснения) — только при
  настроенном провайдере.
- **Погодный контур** и текущий трафик — при желании учитывать фактическую погоду
  и «пробки прямо сейчас».
- **Клиентская регистрация по email-коду** и внешняя интеграция по сети.
- **Первичное наполнение кешей** (дорожные матрицы, геокоды) — один онлайн-прогон
  перед офлайн-эксплуатацией; после него полный рабочий день проходит офлайн.

## Воспроизведение офлайн-демо

```bash
# контур без внешних сервисов: подложка, графы и каталог уже в репозитории
LLM_PROVIDER=replay ROUTER_ROAD_API_OFFLINE=true  # переменные окружения
```

Пошагово — [runbook.md](runbook.md) и [tz-acceptance.md](tz-acceptance.md).
Полный список сверх-ТЗ возможностей — [features.md](features.md).
