# Резервный показ и диагностика

Режимы добавлены по задаче DRO-25. Они не меняют Router, серверные контракты или базу.
Главный экран явно показывает источник данных.

| Режим | Данные и действия |
|---|---|
| Подключено | Проверенные ответы рабочего API и обычные действия диспетчера. |
| Сохранённый план | Последний успешный комплект представлений. Просмотр доступен; запись, импорт и новый расчёт заблокированы. Показано время получения. |
| Демо-сценарий | Записанные результаты Router на 18 заявках и 5 бригадах официального Восточного набора. Переключение сценариев и политик локальное, без API-запросов. |

Сбой не подменяет рабочие заявки учебными. Демо выбирается явно на экране входа
или панели источника. Последняя ошибка остаётся в диагностике после переключения
и после восстановления связи.

## Сохранение рабочего плана

Снимок хранится в `sessionStorage` текущей вкладки: версия формата, время получения,
случайный идентификатор сессии и срок её действия. Контакты и текст проблемы из
копии удаляются, токен не записывается. Перезагрузка вкладки сохраняет копию.
Выход, 401/403 и известное истечение сессии очищают доступ к ней. Срок проверяется
при восстановлении и опросе API. Это резерв просмотра сессии, не офлайн-авторизация.

При запрете записи/переполнении браузерного хранилища живой экран продолжает работу,
но `durableForThisSession` в диагностике будет `false`: после reload остаётся только
общедоступный учебный демо-пакет. Закрытие вкладки обычно очищает sessionStorage.

## Подготовка автономного показа

```powershell
pnpm --filter web build
pnpm --filter web preview --host 127.0.0.1 --port 5186 --strictPort
```

Открыть `http://127.0.0.1:5186/?demo=1` и оставить локальный preview-процесс работающим.
После подготовки зависимостей/сборки интернет и API для этого режима не нужны.
Обычный вход — тот же адрес без `?demo=1`.

Production-сборка устанавливает service worker для файлов приложения и публичного
демо-пакета. После первого успешного открытия и кеширования страницу можно повторно
открыть без сети. API, ответы входа, токены и внешние запросы он не кеширует.
На чистом устройстве недоступный сайт без первого открытия не загрузится: для этого
случая нужен локальный сервер. В режиме Vite dev service worker не устанавливается.

Демо использует фиксированный день **17 августа 2026**. Четыре состояния: начальный
план, дополнительная срочная заявка, недоступная первая бригада, включённые обеды.
Для каждого записаны пять политик и FIFO при одинаковых условиях. Время расчёта
при воспроизведении не измеряется и не выдаётся за 0 мс. «Начать заново» возвращает
исходный сценарий. «Вернуться к серверу» загружает рабочие данные без переноса
демо-изменений и без очереди отложенных действий.

## Карта

При доступной сети все режимы пробуют обычную онлайн-карту. Ошибка провайдера,
ожидание стиля свыше 6 секунд или отключённая сеть включают локальную карту
района демонстрации: реальные улицы, парки и водоёмы OpenStreetMap. Файл
`apps/web/public/maps/east-demo.geojson` включён в офлайн-кеш оболочки; внешние
тайлы, спрайты и шрифты для него не нужны. Есть кнопка повторной попытки онлайн-карты.
Точки, выбор заявки, маршруты и таймлайн сохраняются. При отсутствии WebGL
показано сообщение с предложением использовать список и таймлайн.

Границы, лицензия ODbL, источник, время данных и хэши описаны в
[паспорте карты](../apps/web/public/maps/README.md) и `manifest.json` рядом с ним.
Публичные растровые тайлы OSM не скачивались. Атрибуция видна на карте.

**Ограничение:** это не полный офлайн-атлас Москвы. Вне сохранённой области
полнота подложки не гарантируется; здания и адресные подписи не включены.
Координаты самих заявок по-прежнему проецированы на центроиды районов; реальная
подложка не превращает их в точные адресные точки и пунктир — в дорогу.

## Ошибки и диагностика

- HTTP-запрос ограничен 12 секундами. Неопределённый результат изменения не
  повторяется автоматически и не превращается в локальный успех.
- Ошибка формата не перезаписывает копию. Проверяются схема и ссылки между
  заявками, инженерами и маршрутами. Общую транзакцию нескольких HTTP-чтений
  frontend доказать не может; источником атомарности представлений остаётся sys.
- При потерянном ответе на изменение остаётся отдельное предупреждение.
  Перед повтором нужно сверить серверное состояние.
- Копируемая диагностика содержит режим, ревизию плана, время чтения, HTTP-статус,
  endpoint без query и безопасный request ID. В неё не включаются тела ответов,
  контакты и токены.
- Версия сборки: `VITE_APP_VERSION`, затем Git при сборке; если недоступны оба —
  `unversioned-build` (например, в текущем Dockerfile).

## Обновление записей

Из корня репозитория, в Python-окружении с зависимостями Router:

```powershell
python -m apps.web.scripts.generate-demo
pnpm --filter web test
pnpm --filter web build
```

Генератор `apps/web/scripts/generate-demo.py` читает версионированные ресурсы,
считает политики, валидирует main/FIFO и сохраняет источник/SHA в
`apps/web/src/demo/generated/recorded.json`. Golden-файлы Router не меняются. Метрики и причины
не редактируются вручную ради более эффектного демо.

## Приёмка и оставшиеся границы

`resilience.test.ts` проверяет срок сессии, повреждённый кеш, запрет записи,
межсессионную очистку и согласованность сценариев/метрик. Тесты API-клиента проверяют
таймаут без повторной отправки и сохранение статуса/request ID.

Браузерный прогон: ноль API-запросов из демо; сценарии/сравнение; повторное открытие
без сети; 503 и сохранённый план после reload; невалидный ответ; восстановление;
очистка при 401; desktop и узкий viewport. Сбои моделируются в отдельном браузерном
контексте/тестовом API, без выключения сети Windows и воздействия на публичный стенд.

`pnpm smoke` сбрасывает данные: только отдельный тестовый compose-проект с собственными
портами/томами. Эти проверки не заменяют остальные отказные испытания Router/providers
и сохранности бизнес-данных после перезапуска из исходной DRO-25.
