# Лаунчер Navix

В каталоге `/launch/` находятся четыре точки входа:

| Платформа | Окно | Консоль |
| --- | --- | --- |
| Windows | `windows-gui.cmd` | `windows-shell.cmd` |
| Linux / macOS | `unix-gui.sh` | `unix-shell.sh` |

Нужны Python 3.10+ (для окна — Tkinter), Docker с Compose и полный checkout с данными.
В Windows Python можно установить с python.org; в Linux Tkinter обычно поставляется
пакетом `python3-tk`. Unix-скрипт можно запустить через `sh launch/unix-gui.sh`.
Это исходные переносимые лаунчеры, не автономные бинарные установщики.

Мастер проверяет SHA-256 основных файлов, Docker и сеть, затем запрашивает режим,
порты и настройки. Проверка хешей выявляет повреждения загрузки, но не заменяет
криптографическую подпись издателя. После намеренного обновления исходников:
`python3 launch/update_manifest.py`.

Full запускает UI, API, БД и планировщик. Headless исключает UI и требует порт API;
MCP доступен на том же порту по `/api/v1/mcp`. В Full API можно не публиковать:
UI обращается к нему через внутренний nginx. Порты публикуются только на localhost.
Выключение OSRM исключает OSRM и road-api; расчёт использует комплектные региональные
графы для расчёта; неметро-геометрия отображается прямыми между концами участков.

Офлайн-контур отключает AI, изолирует сеть контейнеров и ограничивает внешние запросы
браузера через CSP. Карта использует локальные данные. OSRM при наличии образа и
комплектного графа работает без интернета. Первая сборка требует сети: перед переносом
в закрытый контур подготовьте образы онлайн, затем перенесите Docker-образы через
`docker save` / `docker load` вместе с checkout и данными. Отсутствующие образы явно
перечисляются при попытке офлайн-запуска. Офлайн-запуск не выполняет pull/build.

Настройки получают по PIN с `https://distribute.droidje.com`, импортируют из `.env`
либо вводят вручную. После получения любого пакета лаунчер всегда отдельно запрашивает
почту и пароль диспетчера; эти значения имеют приоритет над credentials из PIN/.env.
Значения `.env` не исполняются как shell. Локальные настройки
сохраняются в игнорируемом `.launch/`; этот каталог содержит секреты и не предназначен
для публикации. На Windows ограничьте доступ к checkout правами своей учётной записи.
База получает отдельные случайные пароли, стабильные между перезапусками.
Для входа используются введённые при запуске DISPATCHER_EMAIL / DISPATCHER_PASSWORD.
Пароль не хранится в базе: API хеширует значение из окружения при старте. При
существующей базе повторный запуск сохраняет данные и identity базы; тот же email
продолжает использовать тот же аккаунт диспетчера, а новый введённый пароль действует
для последующего запуска API. Смена email соответствует существующей auth-семантике
и может создать отдельный аккаунт, поэтому для сохранения профиля вводите прежний email.

Автозапуск задаёт Docker restart policy `unless-stopped`; это не включает автозапуск
самого Docker в операционной системе. При смене режима лаунчер останавливает только
исключённые сервисы своего проекта `navix-launch`. Данные в именованных томах сохраняются.

Команды управления после запуска:

```sh
docker compose -p navix-launch -f .launch/compose.json ps
docker compose -p navix-launch -f .launch/compose.json stop
python3 -m unittest launch.test_core
python3 -m unittest discover -s services/distribution
```

Сбой Docker возвращает путь к `.launch/docker.log`. Диагностика приватная: она может
содержать настройки. Повторный запуск не удаляет тома и не затрагивает другие проекты.
