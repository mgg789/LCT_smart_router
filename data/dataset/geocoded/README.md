# Геокод-пакеты официального датасета ТЗ

Версионированные каталоги координат для импорта «Из ТЗ» (`dataset-import.service.ts`):
по записи на каждый адрес заявки плюс депо региона, схема `geocodePackageSchema`
(`schema_version`, `version`, `source`, `entries[address, node_id, location, match_level, source]`).
Пакеты покрывают адреса **`<регион>_synthetic_data.csv`**; контрольные распределения
адресов не добавляют. Рядом лежат пакеты **`<region>-extra-days.json`** — адреса
дополнительных дней организатора (28–29.09.2026, см. `data/dataset/extra-days/`);
табличная загрузка мерджит все `*.json` каталога, импорт «Из ТЗ» читает только
базовые `<region>.json`.

## Текущая разметка — LocationIQ, 2026-09-29

- **Источник:** LocationIQ (Nominatim/OpenStreetMap), форвард-геокодинг адресов
  организатора; поиск ограничен боксом Москва + юг Московской области
  (`viewbox=35.8,56.3,39.8,54.2&bounded=1`) — отсекает одноимённые улицы в других
  регионах (например село Каширское Воронежской области вместо Каширы).
- **Версии:** `official-<region>-geocodes-locationiq-2026-09-29`
  (`east` — 66, `south_central` — 56, `southeast` — 76 записей).
- **Покрытие:** 198/198 адресов; 192 точки — house-level (здание/дом),
  6 — уровень улицы/площадки, потому что полигонов дома в OSM нет:
  Зеленодольская 28Б, Самаркандский б-р (Квартал 137А), Кленовый б-р 10к1
  (стройка), Домодедово, 1-й Советский пр-зд 1А, Домодедово Гагарина 55/2,
  Бирюлёвская 1с1.
- **Бюджет:** 60 запросов/мин, ответы кэшировались; адреса организатора
  написаны с опечатками/омонимами — для 19 адресов заданы ручные запросы
  (`MANUAL_QUERIES` в инструменте), в т.ч. дроби «5/1..5/3» в Кашире = корпуса
  «к1..к3» в OSM, «пгт Востряково-1» = мкр. Авиационный в OSM (дом 14/18
  совпадает байт-в-байт).
- **Воспроизведение:** `data/tools/geocode_locationiq.py` (токен — только через
  переменную окружения `LOCATIONIQ_TOKEN`; рабочий каталог собирается как
  `datasets/` + `original_packages/` + скрипт, см. docstring).
- **Отчёт:** построчная сверка (адрес → координата → match_level → сдвиг от
  прежней точки) хранится рядом с рабочим каталогом разметки; сводка — в коммите
  этого пакета.

Прежние пакеты (детерминированные проекции адресов на центроиды районов,
haversine-приближение) хранятся в `context/legacy_data/geocoded-centroid-2026-09/`.
