# Доп. дни организатора — 28 и 29 сентября 2026

Преобразованные таблицы заявок «Доп дни» (raw-выгрузка организатора, cp1251 + `;`),
положены рядом с основными таблицами ТЗ из `data/dataset/anonymized/`. Загружаются в
приложение через панель табличной загрузки (анализ → предпросмотр → импорт):
колонки «Заявка / Тип заявки HD / Начало / Окончание / Район / Адрес» распознаются
алиасами табличного парсера, координаты подтягиваются из геокод-каталога
(`data/dataset/geocoded/`, включая пакеты `*-extra-days.json`) по нормализованному
адресу.

## Что было сломано в raw-выгрузке и как это исправлено

Инструмент: `data/tools/transform_extra_days.py` (правила — в его docstring).

1. **Имена файлов врут о дне.** Пара юго-востока перепутана местами: «юго-восток
   день 2» содержит 29.09, «юго восок день 3» — 28.09; оба файла «юго-центр день
   2/3» содержат только 28.09. Правило преобразования: день строки берётся из её
   собственной колонки «Начало», никогда из имени файла; выходные таблицы названы
   по реальной дате.
2. **Номера заявок повторяются.** 89 номеров встречались более чем в одном файле:
   76 — байт-в-байт одинаковые снимки одной и той же строки (схлопнуты, дубликат
   отбрасывался), 13 — реальные переносы заявки на другой день (тот же номер BK,
   новое окно и более поздний статус). Переносы сохранены как есть: по строке в
   каждой дневной таблице, номера внутри одной таблицы уникальны.
3. **Битые написания адресов** («д. к7», «6 к Б», «мкр..Западный», город без
   запятой, «пр-зд.») — не правились в таблицах: табличная загрузка джойнит по
   нормализованному адресу, а точки для них геокодированы по ручным запросам
   (`MANUAL_QUERIES` в `data/tools/geocode_locationiq.py`).

## Геокод-пакеты доп. дней

`data/dataset/geocoded/{east,south_central,southeast}-extra-days.json` — 340 новых
адресов (20 адресов уже были в пакетах дня 1 и переиспользованы). Разметка
LocationIQ/Nominatim, бюджет 110 запросов/мин (`LOCATIONIQ_RPM=110`), тот же бокс
«Москва + юг МО» против омонимов. 328 точек — house-level, 12 — уровень улицы/стройки
(OSM-гэпы: Самаркандский б-р, Болотниковская 6Б, Кленовый б-р 7, Загорьевская 16к2,
Крутицкая 5, Каширский пр-зд 11, Домодедово Гагарина 55/1, Кашира Гвардейская 4/2 и
др.). Пакеты дня 1 (`<region>.json`) не менялись — импорт «Из ТЗ» детерминирован.

## Особенности данных

- Колонки «Статус BK» и «Тип заявки BK» сохранены как есть; статусы жизненного
  цикла («Выполнена», «Отменена», «Просрочена», «В работе»…) — факты выгрузки, на
  планирование в табличном импорте не влияют.
- Типов работ 21 (против трёх в дне 1), включая «Авария» и «Информация»
  («Глобальная проблема»). Известные каталогу маппятся автоматически; неизвестные
  табличный импорт помечает и просит выбрать группу (Авария / Подключение /
  Ремонт-Дозаказ) на предпросмотре — исходное название сохраняется.
- Дробные дома Каширы «5/1..5/3» из дня 1 здесь не встречаются; новые каширские
  адреса («Ленина 9» = Кашира-3, не Ожерелье) разрешены вручную.
