## Рабочий процесс

1. Уточните задачу и критерии приёмки; используйте существующую карточку проекта.
2. Проверьте ветку и рабочее дерево, сохраните чужие незавершённые изменения.
   Обновите `dev` без переписывания истории. Обычно задача выполняется в короткой
   тематической ветке от `dev`; работа непосредственно в `dev` согласуется с техлидом.
3. Переиспользуйте существующие компоненты и контракты. Не включайте посторонние правки.
   Статические тексты UI добавляйте в `apps/web/src/i18n/ru.ts`, используйте `t()`;
   сохраняйте доступные названия контролов и клавиатурную навигацию.
4. Добавьте необходимые тесты и обновите документацию вместе с кодом. Для контрактов
   проверьте миграции, генерацию и совместимость потребителей.
5. Перед слиянием выполните подходящие проверки и обязательный smoke. В описании PR
   укажите проблему, изменение поведения, выполненные команды и известные ограничения.
6. Коммиты — Conventional Commits, например `fix(web): preserve modal focus`.
   Сливайте в `dev` после ревью и зелёных проверок, сохраняя значимые контрольные коммиты.
   `main` обновляет техлид явным слиянием из `dev`; прямой и force-push запрещены.

## Запуск и проверки

Версии Node.js и pnpm указаны в корневом `package.json`. Установка —
`pnpm install --frozen-lockfile`; настройка сервисов и окружения — по
[README](README.md) и [runbook](docs/runbook.md). Секреты храните вне Git.

```sh
pnpm lint
pnpm --filter web typecheck
pnpm --filter web test
pnpm --filter web build
pnpm test:i18n-lint
pnpm lint:a11y
```

Для API/маршрутизатора используйте профильные команды из документации подсистемы.
`pnpm smoke` и `pnpm test:regression` требуют подготовленного тестового окружения:
не направляйте их на рабочую базу со значимыми данными. Прохождение lint не заменяет
проверку сценария в браузере; ограничения проверки явно отмечайте в PR.

## Безопасность и эксплуатация

Не коммитьте `.env`, ключи, сессии, дампы с персональными данными и артефакты сборки.
Не меняйте чужую инфраструктуру и не удаляйте данные без согласованного плана.
Для уязвимостей используйте закрытый канал из [SECURITY.md](SECURITY.md).
